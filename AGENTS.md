# LuMap development and publishing

The standalone public repository for this project is:
https://github.com/Ar1haraNaN7mI/LuMap---Celestial-Frontier

Publish the contents of this Lumap directory as that repository's root. The surrounding VoiceRecord/VoiceClass repository is a separate legacy workspace. Do not upload its unrelated files to the LuMap repository.

Use the current sequential learning contract: show the current section and completed history only, let the model assign the section's ordered methods, save assessed evidence before continuing, and adapt the next section using that evidence. Do not restore an all-method picker or fixed template curriculum in the main learning flow.

Keep AR previews explicitly identified and distinguish the implemented model-and-constraints policy from the planned trained RL model. Provider failures must produce bounded, recoverable errors, never fake generated content.

Keep the public README detailed and in English, with real product images and verified relative links. API keys, SwiftData stores, private user material, runtime voice weights, local build output, and temporary validation runs must never be committed. Keep provider credentials in Keychain. Generated media examples must be free of private learner data.

Before publishing, run macOS tests, build the iOS Simulator target, and check actual model behavior separately from offline tests. Use XcodeGen after changing shared source inclusion. Avoid simultaneously running same-bundle Xcode test hosts and computer-use app restarts.
