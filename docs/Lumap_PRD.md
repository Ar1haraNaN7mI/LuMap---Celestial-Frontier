# Lumap 产品需求文档

团队名称：**Celestial Frontier**

全年龄多领域自适应学习平台

版本 0.7　｜　2026 年 9 月 30 日　｜　状态：产品设计与可运行 MVP 对齐

Lumap 面向不同年龄、背景和能力的学习者，覆盖理论知识、实践技能、创作、语言、职业与生活学习。用户可以直接输入想学的内容，也可以从基于个人兴趣的“猜你想学”开始。进入学习后，系统组合不同学习方式，根据可观察的效果调整方法和内容，并通过可选检测、个人进度、奖励及桌面 Persona 支持持续学习。

本版按最新产品要求重写。个人社交媒体的默认绑定方式为粘贴主页链接，由 AI 分析公开可访问内容；搜索记录和电脑使用习惯通过独立授权的数据入口接入。全年龄、多群体、多类型是产品定位，具体内容、平台和硬件支持通过能力清单逐步扩展，不将有限的 Hackathon 演示覆盖误写成完整产品能力。

**本版关键决策：** 开屏突出“你今天想学什么”、输入框、上传资料和轻量“猜你想学”。进入课程后只显示当前小节，模型根据个人背景、目标和证据安排 1–3 种学习方式；用户完成当前安排后才进入下一活动或下一小节。未来小节和总节数不作为目录展示，也没有全部方法下拉菜单。Guided Study 共用这一流程并增加来源查看与引用问答。项目、进度、反馈、方法轨迹和奖励集中于个人页；Persona 延续当前学习。外观主题全部开放，Lumens 用于 AI 学习额度及未来实物奖励。工作区使用真实资料、模型和本地学习记录；AR 为明确标记的独立概念预览。

本文面向 Lumap 产品、设计、开发及 Hackathon 团队。除已明确的用户要求和引用的接口事实外，参数、开发时长、商业模式与效果阈值均为待验证设计。Lumap 0.1.0 已完成本地 Hackathon 演示闭环；本文仍描述完整产品目标，不能把目标能力视为当前已交付功能。当前应用可以抓取用户主动提交且公开可访问的主页；历史数据仅在主动选择 CSV/JSON 后本地导入，不持续读取搜索历史或电脑行为。

## 0.7 顺序式个性化学习交付增补

此节定义当前 MVP 的实际行为，优先于后文保留的早期原型说明；长期 RL 训练、视觉监督、家庭与云端服务仍按目标方案分期。

- **输入即编排**：保存原始目标后检索公开资料并编排内部课程。模型按学习者的已有基础、目标范围和时间安排 2–12 个内部小节，每小节初始安排 1–3 种方式；数量不是固定六节或固定十七项。界面只揭示当前小节，未来显示“下一步，会随着你的学习逐渐成形”。
- **用户资料优先**：上传资料或多材料选择建立课程时使用选中摘录，不将私有内容作为公开搜索查询；回答保留来源 ID 和可查阅摘录。
- **教学方式真实生成**：解释、例题、苏格拉底对话、类比、概念图、剧情、回忆、复述、模拟、刻意练习、反思、误区诊断、好奇分支、反事实与迁移任务均取材当前课程。先回答再翻卡，分步揭示，具体任务评分，避免只凭输入长度判分。
- **完整讲解课程**：至少 5 页、每页完整教学稿、至少 2 个 Quiz。Kokoro 完整朗读后再显示章节问题，支持自动续播、暂停、切页、重听和取消；全部页听完且回答所有 Quiz 后才能保存完整学习证据。支持教学稿、可编辑 PPTX 和教学视频导出；视频保留提问及思考时间，应用内提供点击式 Quiz。
- **顺序与自适应**：方法状态仅显示进行中、已完成与本节后续，不提供手动跳转。已保存的当前尝试决定下一活动；低分留在本小节，由模型安排补救。全部必需方式形成达标证据后，`adaptSection` 根据最新回答、误区和方法表现实际请求模型重新编排下一小节。当前是 LLM 加本地约束策略，不是已训练的 LumaPath-RL。
- **进度来自证据**：一般练习给出 0–100 形成性反馈，当前达标阈值为 70。本节全部必需方式完成并形成达标证据后才完成小节；模型指定的补救成功可解决之前失败项。保存、看完或答题字数本身不代表掌握，纠错不重复领取同一活动奖励。正式 Theoretical/Practical 检测仍可选，与日常必需活动分开。阈值仍需试点校准。
- **可恢复学习包**：计划、活动、回答、反馈和当前节点按目标保存在 SwiftData，课程切换不复用别的主题。手动导出/导入学习包实现 macOS/iOS 接力，包含来源和学习证据但不包含 API key、个人背景、供应商配置或奖励余额；不声称已实现自动云同步。
- **外部内容边界**：主页无法访问时显示原因，不编造兴趣；AR、世界追踪和视觉实验监督仍是显式视觉演示。Persona 根据应用内课程和学习状态互动，不声称监控真实电脑行为。

- **有界等待**：课程、活动、评估及小节适配的结构化模型调用含一次修复在内共用 90 秒预算；活动界面有已等待秒数、停止、错误与重试，120 秒本地看门狗解除异常等待。网页检索、旁白和媒体导出属于独立阶段，不能把 90 秒称为完整视频生成时长保证。失败不伪装成功，也不替换为固定课程。

新增验收：不同主题和不同学习背景产生相应课程；未完成当前活动不能继续；未完成本节全部安排不能揭示下一节；下一节出现前发生真实适配调用；低分补救留在当前小节；恢复保持已完成方法与当前方法；完整旁白时长与视频音轨一致，所有课件页出现在导出文件。

验证快照（2026-09-30，最终回归）：常规 macOS 套件共 60 项，58 项通过，2 项真实服务/媒体测试默认跳过，0 失败；macOS 与 iOS 构建通过。独立真实服务测试已验证光合作用与特征向量生成不同资料及课程、错误/正确回答得到不同评分，以及双资料精确引用问答与资料课程生成。光合作用示例已导出 6 页 PPTX、622 词完整讲稿和约 240.82 秒带音轨 MP4；这些是具体运行证据，不是全年龄效果或训练后 RL 的验证。

## 01 产品定位与体验闭环

### 01 1 核心问题与价值

学习者既可能有明确目标，也可能不知道从哪里开始；不同知识需要不同学习活动，同一个人适合的方法也会随主题、基础、精力和设备变化。Lumap 需要回答三个问题：现在学什么、怎样学更有帮助、有哪些证据说明取得了进展。

产品闭环为“了解用户与当前意图 → 推荐或直接进入主题 → 组合学习模块 → 根据反馈调整 → 可选效果检测 → 保存成长轨迹与奖励 → 通过 Persona 延续学习”。用户可以暂停、结束或另建学习目标，也可以纠正背景、资料和互动强度；当前课程内的方式与小节按模型安排顺序推进。

一句话定位：Lumap 是一个结合个人兴趣、学习表现和当前情境，为不同学习者持续安排内容与学习方式的 AI 学习伙伴。

英文介绍建议：Lumap helps you explore what to learn, discover what works for you, and see your progress across knowledge and practical skills.

### 01 3 差异化与验证重点

引导式 AI 辅导已经存在，Khanmigo 官方也描述了引导思考的体验。Lumap 的差异化假设是将跨来源兴趣、动态学习模块、可选双类检测和桌面陪伴连成一个可解释、可控制的过程。应验证这套组合的价值，而不是宣称没有同类产品。[Khanmigo 官方介绍](https://www.khanmigo.ai/)

## 02 全年龄全群体全类型的适配

### 02 1 年龄与个人信息

初次设置提供年龄或年龄段、内容语言、个人背景、感兴趣主题、学习目的、可用时间和表达支持选项。年龄用于内容适宜性、互动长度及账号功能边界，不用于自动判断学习基础。职业、教育经历和已有技能由用户自述，不能直接视为已验证能力。

用户可跳过非必要背景；年龄未知时采用保守内容范围，提供基础学习，并在进入受年龄限制功能前补充适用的年龄确认。默认不要求精确生日、真实姓名、学校全名或家庭住址。共享电脑支持显式切换学习档案，Persona 状态和来源绑定跟随当前档案；H0 可先实现单档案及明确标记的演示档案。

| 用户或情境 | 应适配的体验 | 不应作出的推断 |
| --- | --- | --- |
| 学前及初学表达者 | 短句、图像选择、共学模式、短活动 | 不会打字不等于不理解 |
| 学龄与青少年 | 年龄适宜内容、具体目标、可控奖励 | 年龄不等于学科水平 |
| 大学生与职业学习者 | 资料导入、项目任务、理论与应用切换 | 专业名称不等于掌握全部前置 |
| 转行与成人兴趣学习者 | 实际场景、已有经验迁移、灵活节奏 | 兴趣不能决定职业适配结论 |
| 老年学习者 | 大字号、低操作负担、重复说明可选 | 年龄不等于记忆或技术能力低 |
| 不同语言与可访问性需求 | 字幕、键盘、语音或文字替代、减少动画 | 表达速度与交互方式不等于智力 |

### 02 2 学习内容类型

| 类型 | 学习模块例子 | 可选检测例子 |
| --- | --- | --- |
| 概念与理论 | 类比、图解、思辨、检索练习 | 解释、比较、论证、迁移问题 |
| 数学与计算 | 分步示例、推演、参数实验 | 解题与说明选择理由 |
| 编程与数字技能 | 示例修改、调试、项目操作 | 测试用例、操作结果、错误定位 |
| 语言与沟通 | 对话、情景角色扮演、复述 | 场景表达、理解与回应 |
| 艺术与创作 | 范例分析、模仿、创作实践 | 作品约束、意图表达与反思 |
| 生活与职业技能 | 流程示范、任务分解、情景模拟 | 可观察操作步骤与结果 |
| 科学与实验 | 变量探索、模拟实验、观察记录 | 实验设计、数据解释与实践过程 |

“全类型”要求可扩展的活动与评估架构，不意味着一种评分量规适合所有学科。涉及身体动作、设备或实验环境的任务必须声明所需工具、监督条件和系统能够观察的范围；风险较高的操作只提供合适的模拟或教学信息，不由桌面视觉结果宣称已经获得现实操作资格。

### 02 3 年龄与外部账号相容

全年龄使用不能依赖每个人都有社交账号。澳大利亚 eSafety 当前说明，受限制平台须采取合理措施防止澳大利亚 16 岁以下用户持有账号。因此，相关用户仍可通过手动兴趣、选择资料、家长或共学者提供的适龄材料使用 Lumap，不引导借用成人账号绕过平台年龄要求。成人提供的材料标记为“共学者提供”，不当作儿童自己的行为轨迹。[eSafety 家庭说明](https://www.esafety.gov.au/parents/social-media-age-restrictions)

儿童及共学流程从产品架构阶段纳入；实际公开版本需完成适龄内容、监护权限、数据控制和目标人群测试。监护者可管理内容范围、外部来源与提醒时段，但默认不获得全部私人对话。此处定义产品原则，不宣称所有地区的发布要求已经完成。

## 03 个人主页链接与资料建立

### 03 1 默认绑定流程

绑定入口名称为“Add your profile link / 添加个人主页链接”。用户粘贴一个或多个自己的公开主页地址，系统显示平台、主页名称和可访问性，并请用户确认该链接属于自己的学习档案。这是用户声明，不应显示“账号所有权已验证”。也可把其他链接作为学习素材添加，但不能混入个人行为画像。

流程为“粘贴链接 → 检查地址与公开可读性 → 读取有限范围的公开内容 → 提取候选兴趣 → 显示来源和可用内容量 → 用户保留或纠正标签”。绑定后将该来源允许用于学习推荐，后续更新仍受来源开关和更新频率控制。首屏学习不必等待主页解析完成。

### 03 2 抓取范围与失败处理

初始抓取限定用户提供的主页及同一作者的公开内容页，不沿粉丝、评论者或好友关系扩张成他人档案。建议首轮上限为近 90 天可访问的 30 条内容、最多 30 个页面及 60 秒任务预算；具体限额根据平台允许方式和测试结果调整。大视频只处理可访问标题、简介和用户选择的字幕，不默默下载完整媒体库。

简介、帖子正文、标题及公开主题可形成兴趣候选；关注、点赞、收藏只有确实公开且能够明确归属于该用户时才使用。发过一次内容可能是转发、工作任务或讽刺表达，不应直接形成高确定性兴趣。

| 来源状态 | 展示 | 后续动作 |
| --- | --- | --- |
| 可读取公开内容 | 已分析的条数、时间范围与出处 | 生成可纠正的候选标签 |
| 只读到简介 | 部分可用，内容不足 | 用低影响标签，建议补充具体帖子 |
| 需要登录或遇到访问限制 | 该主页暂无法读取 | 用户可粘贴内容、上传导出文件或换链接 |
| 链接失效或不支持 | 地址或平台不支持提示 | 保留输入，提供手动兴趣入口 |
| 解析超时或用户取消 | 已停止，未完成部分清楚 | 不伪造画像，可重试 |
| 数据更新后与旧标签冲突 | 标签变化及其来源 | 保留用户明确纠正，允许重新确认 |

接入实现优先使用平台允许的公开读取或正式接口；是否需要额外账号授权由具体适配器决定，不能把“粘贴链接”宣传成能读取登录态、私信、非公开收藏或观看历史。用户确认链接属于自己也不会消除平台访问限制。例如 YouTube 官方明确其 Data API 无法取回观看历史，公共主页更不能被当作完整观看记录。[YouTube playlistItems 错误定义](https://developers.google.com/youtube/v3/docs/playlistItems/list)

### 03 3 更新与解除绑定

默认由用户手动刷新；可选自动更新建议最多每日一次，失败采用退避，不反复轰炸来源。解绑立即停止新抓取，并提供“同时移除该来源生成的标签与摘要”选项；若用户只停用，旧数据可保留供查看，但默认不再参与新推荐。

用户明确确认的兴趣可在来源删除后作为独立自述保留，但必须事先说明并由用户选择，不能自动转换来源规避删除。同一帖子跨平台转载按内容哈希去重，避免被计作多个独立证据。

## 04 搜索记录电脑习惯与标签模型

### 04 1 数据来源独立授权

| 来源 | 可使用的信息 | 获取与控制方式 |
| --- | --- | --- |
| 个人填写 | 年龄段、语言、目标、兴趣、经验 | 可修改；非必要字段可跳过 |
| 公开社交主页 | 实际可读的简介、内容和主题 | 粘贴链接后按来源启停与删除 |
| 浏览与搜索记录 | 授权浏览器内可见的页面主题和可解析查询 | 扩展权限或用户选择的导出文件，限定时间和站点 |
| 电脑使用习惯 | 前台应用类别、使用时段、会话切换 | 独立开关和观察时段，本地事件汇总 |
| 学习活动 | 方法选择、提示、练习产出和主动反馈 | 用于当前学习，跨会话使用可控制 |
| 可选检测 | 理论或实践证据、条件、评分和时间 | 用户主动开始，可中止、申诉、删除 |
| 可选画面感知 | 指定窗口或摄像头内的学习场景 | 逐次选择范围，明显工作指示与停止入口 |

Chrome 的 history 接口需要浏览器扩展声明 history 权限。它提供访问记录；搜索查询只在特定访问 URL 等数据中实际出现且可解析时才可提取，不等于能够读到所有搜索引擎账号历史。H0 可先支持用户导出并选择的记录；实时扩展是独立交付，不直接读取浏览器私有数据库。[Chrome history 文档](https://developer.chrome.com/docs/extensions/reference/api/history)

macOS 的 NSWorkspace 应用激活通知可以用于前台应用切换事件，不提供该应用中的具体页面或文档正文。屏幕内容需要另外的捕获路径和用户选择；不能用“电脑习惯”授权替代屏幕、麦克风或摄像头授权。[Apple 应用激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification)、[Apple 内容共享选择器](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker)

### 04 2 标签分层

系统将信息拆为兴趣主题、当前学习目标、明确背景、情境偏好、方法偏好、方法效果和概念薄弱点。每条记录保存来源、时间、观察范围、确认状态、支持数量和到期时间。“可能喜欢摄影”与“已能手动控制曝光”必须是不同对象。

兴趣证据优先级为当前明确选择、用户确认、反复主动内容互动、公开内容推测。一次点击或打开软件仅提供弱线索；阅读时间长可能是困难或分心，不能直接解释为兴趣高。用户纠正优先于旧数据量；不存在历史时标签为未知，不生成虚构经历。

不从社交内容或电脑行为自动推断健康、心理诊断、性取向、宗教、族裔、政治立场或智力等级等敏感个人标签。用户主动学习这些主题不等于具有对应身份。适配需求应允许直接填写，例如“更大字号”或“只用文字”，不必提交医学信息。

### 04 3 信号融合与变化

同一主题的多来源信号保留冲突，不强行合并。例如用户常看摄影帖子但说“最近想学木工”，首页直接输入木工具有最高优先级；摄影仅可能进入后续探索备选。自动标签默认在 30 天无新依据后降低影响，具体时长为试点参数；明确偏好在用户修改前保留，但可周期性邀请复核。

界面使用“你填写的”“你确认的”“AI 暂时推测”区分依据。可删除单项、关闭某个来源、暂停所有跨会话个性化，或者清除画像。关闭后仍能用手动目标和当前会话学习；拒绝外部数据不减少基础学习功能和奖励。

## 05 首页与猜你想学

### 05 1 首页布局和直接进入

开屏采用低干扰的对话入口：中央大标题“你今天想学什么 / What do you want to learn today?”、一个支持多行的输入框与提交按钮；其下只有“想学习上传的文本”和紧凑的“猜你想学”。已开始项目、继续学习、进度、奖励和成长反馈不在首页展示，统一进入 Personal。用户提交明确主题后立即创建该主题的学习会话并进入 Learning Studio；系统在会话内提出初始活动和可选目标细化，不把用户送回兴趣问卷或其他推荐主题。

“我想学摄影”虽然宽泛，仍应进入摄影的起步探索；只有输入确实无法判断主题时才进行一个简短澄清。用户可以修改难度、目标、时间和教学语言，系统可以建议补基础，不能因社交画像认为用户“应该学别的”而更改主题。

### 05 2 猜你想学卡片

输入框下方显示视觉体量较小的“猜你想学 / Ideas for you”，默认四个紧凑候选，旁边固定按钮“不感兴趣，换一批 / Not interested · Refresh”。候选显示主题与一条推荐理由，详细成果、预计投入和方法在进入后展开，避免首页重新变成课程仪表盘。点击后按所选内容进入学习，与手动输入拥有相同优先级。

示例卡片可以是“用手机拍出浅景深效果”“解释一条 AI 新闻的准确率”“用十分钟认识基础和弦”“做一个简单预算表”。这些是卡片结构示例，并非当前已实现课程。

无个人数据时显示跨主题的适龄探索卡，不冒充个性化结果；有公开主页但解析仍未完成时先使用手动标签，完成后仅更新未操作的候选，不在点击或输入过程中跳动替换。

### 05 3 不感兴趣换一批

一次点击替换当前批次，保持页面和输入框状态。该动作表示本批候选不合适，默认只对被展示的具体内容产生短期负反馈；不能推断用户永久讨厌其全部领域。单卡菜单另提供“少推荐这个主题”“太简单”“太难”“已经了解”。

建议最近 20 张已展示卡片在同一轮探索中不重复；被明确排除的主题在用户撤销前过滤。候选不足时显示“新建议暂时不多”，允许扩大领域、调整时间或恢复之前内容，不能把同一课程换标题伪装成一批新建议。刷新是内容操作，不触发重新抓取所有社交主页。

连续三次换批后出现可忽略的轻量偏好选择，用户仍可继续输入或换批。加载失败保留上一批可用卡片和重试入口。点击卡片与刷新并发时，以用户已经点击的课程 ID 为准，不启动后来替换的卡片。

## 06 学习路径与用户控制

### 06 1 从宽到窄与当前小节

先围绕用户目标定位必要基础、核心能力与应用，再根据年龄段、已有基础、时间预算和已确认兴趣生成 2–12 个内部小节。该内部计划是可修订的先修结构，不是一次性展示给用户的固定目录。节点 ID、引用、顺序和无环先修关系需验证。

Learning Studio、Guided Study、移动端活动页和工作区均只显示当前小节的标题、目标和本节安排；已完成标题可作为历史查看。未到达的小节不显示标题、总节数或可点击入口，只显示“下一步，会随着你的学习逐渐成形”。不允许通过路径图、方法库或资料学习入口绕过顺序约束。

### 06 2 学习状态与下一步

主流程为“选择目标 → 检索与初始编排 → 当前小节的当前活动 → 保存并评估 → 补救或下一活动 → 本节完成 → 真实适配下一小节”。每小节初始分配 1–3 种方法，只读状态卡区分当前、已完成和本节后续。模型可根据失败证据在本节加入针对性补救。

未保存有效尝试时，下一步不可用。低分活动可进入模型安排的补救，但不能解锁未来小节；本节全部必需方式完成且形成达标证据后，唯一的下一小节按钮触发 `adaptSection`。模型使用本节回答、误区、方法表现和用户背景修订下一节目标及方式，成功验证后才呈现。失败保留当前节与证据，显示原因和重试；不能凭点击直接推进。

用户可以暂停、结束、请求解释或从首页另建目标；旧项目及记录保留。更换方式是向模型表达支持需求，不提供任意方式下拉框或固定偏好按钮。外部网络故障、未作答和请求提示不当作学习失败。设备与适龄约束作为独立条件，AR 预览不推进正常课程。

### 06 3 独立进度与证据

分别记录已接触、活动产出、活动评分、正式检测和保持证据。当前阈值 70 是形成性反馈参数；某种方式的达标证据或成功的对应补救完成该项，本节全部必需项解决后完成小节。重复提交不重复奖励。正式检测仍可跳过，但跳过正式检测不等于可以绕过本节的日常学习活动。

恢复按目标读取内部计划、当前节点、当前方法、本节完成记录与活动缓存。到达课程终点时显示完成状态和个人进度入口，不显示一个无法生成内容的下一小节按钮。

## 07 Learning Method Modules

### 07 1 模块目录

一个模块是一段具备目标、输入、活动、产出和反馈机制的学习单元，不能只把相同段落换颜色称为不同学习方法。

| 首批模块 | 用户实际做什么 | 可观察产出 |
| --- | --- | --- |
| Guided explanation 引导讲解 | 从系统、变化或证据角度建立心智模型 | 观察角度与自述联系 |
| Worked example 示例拆解 | 按顺序查看完整推理，再提炼可复用规则 | 步骤理解与迁移规则 |
| Socratic dialogue 启发式对话 | 回答信念、反证与新情境问题 | 多轮推理轨迹与修订 |
| Analogy 类比 | 选择熟悉系统，说明映射及失效边界 | 类比关系与边界 |
| Visual map 概念图 | 添加带关系标签的概念连接 | 节点和关系网络 |
| Story 剧情学习 | 在视觉小说场景中选择分支并完成理解检查 | 分支选择与核心认识；包含 Paper2Galgame 风格案例 |
| Flash recall 闪卡回忆 | 先凭记忆作答，再显示提示并标记结果 | 记住／需复习计数与难点 |
| Teach back 反向讲解 | 向 Persona 或初学者解释并请求反馈 | 用户说明、因果与例子 |
| Simulation 互动模拟 | 先预测，再改变变量并比较结果 | 预测、参数、观察结论 |
| Spatial AR 空间实验 | 缩放空间对象、放置学习锚点并记录变化 | 锚点、空间参数与观察；不支持时回退 2D |
| Deliberate practice 刻意练习 | 选择薄弱维度、完成小练习、自评并修正 | 首次尝试、标准对照和改进计划 |
| Reflection 反思 | 分开记录信心、意外、不确定性和下一行动 | 结构化反思与后续动作 |
| Misconception diagnosis 误区诊断 | 选择最接近自己的错误模型，用反例定位断裂的推理环节 | 误区类型、反证与修正后的解释 |
| Curiosity branch 好奇分支 | 从当前概念提出的多个“为什么／如果”问题中选择下一条路径 | 所选问题、探索分支与新问题 |
| Counterfactual lab 反事实实验 | 改变一个关键假设，比较原世界与替代世界的结果 | 假设、预测、差异和边界 |
| Transfer challenge 迁移挑战 | 在陌生案例中辨认相同结构，并指出表面差异 | 新情境映射、结构与失效条件 |
| Narrated lesson deck 讲解课件 | 生成 PPT 风格幻灯片，播放拟人旁白，随机插入小 Quiz | 幻灯片摘要、已播放页、答案与即时解释 |

17 种类型构成能力目录，其中 16 种非 AR 学习形式由模型按需安排，AR 独立预览；不把目录作为活动切换器。每类交互需要可操作案例，但不要求一个学习者遍历全部方法。后续仍可加入动作练习、代码项目、音频练习或更专业的实验 renderer，但不能把相同文本换皮计为新方法。

视觉、音频、文字是表现通道；讲解、检索、实践、迁移是活动方法。两者分别记录，避免把“喜欢图像”直接等同于“图像教学总是最有效”。用户的无障碍配置优先于方法探索。

### 07 2 模块统一协议

输入至少包含当前目标、目标概念或技能方面、已有证据、内容来源、学习语言、可用时间、设备、适龄范围和用户明确偏好。模块声明所需输入方式、允许的辅助、预计产出以及是否需要摄像头等额外能力。

输出包括实际活动、用户选择、是否完成、使用的支持、学习产出及其可评估性。方法效果估计只使用有效且可比较的结果；模块完成但未提供可评估产出时，记录完成和体验反馈，不强行推导提升。

各模块共用暂停、解释、结束和顺序继续入口。方法变化由当前小节安排或模型补救决定；必须保留目标、相关资料与已完成证据，不能把变化变成重复播放相同文本。

### 07 3 模块组合

模型可为同一小节安排一个方法，也可组合 2–3 个互补方法，例如“例题 → 主动回忆 → 讲解复盘”。依据是学习者背景、实际内容、目标时长和已有回答，不机械套用固定模板。预计时间不作为强制倒计时。

界面显示只读状态卡，不能点击后续方法或从全部方法中自行跳转。当前活动产生证据后，模型根据错误与成功情况维持、补救或继续安排。无障碍限制、用户明确困难和不适用通道进入模型上下文与本地约束，不能强迫使用不可操作形式。

### 07 4 讲解课件、拟人旁白与随机 Quiz

讲解课件将当前目标、允许使用的资料摘录、教学语言和学习者上下文转换为 5–8 页结构化幻灯片。每页包含标题、要点、视觉类型、完整讲稿和可选 Quiz；模型只返回受版本约束的 JSON，不返回可执行 SwiftUI 或 HTML。用户可前后翻页、播放、暂停、继续、停止、静音，并在 Quiz 中看到即时解释。保存产出时记录课件标题、各页摘要、实际播放页和 Quiz 结果，不能只记录“看完”。

已保存完整供应商配置时，课件先尝试实时生成；只有响应通过版本、页数、视觉枚举、Quiz 选项和字段完整性校验才进入界面。未配置时显示配置入口；网关、模型或合同失败时显示错误与重试，不自动退回固定演示。讲解课件仅在被安排到当前小节时进入学习流程，不作为任意方法切换入口。Responses 接口支持填写 `/v1` 基础地址或完整 `/responses` 路由。供应商当前分组与录屏前排障步骤见 [自定义模型供应商运行手册](Custom_Model_Provider_Runbook.md)。

旁白采用 Apache 许可的 Kokoro 开放权重与 sherpa-onnx Apple 平台运行时，在设备上生成中英拟人语音。应用不调用 Apple 系统 TTS，也不在语音包缺失时静默回退；缺包状态明确显示并保留字幕、时间线与 Quiz。模型权重约百兆级，独立下载、校验 SHA-256 后安装，不提交到 Git。大模型 API 负责生成课件与 Quiz，Kokoro 只把讲稿转成声音，两种模型和密钥边界分离。详见 [开源语音技术方案](Open_Source_Voice_Integration.md)。

### 07 5 Guided Study 资料学习

Guided Study 与 Learning Studio 共用同一个当前小节、模型安排、完成记录和继续条件。旧版 Understand → Question → Retrieve → Teach back 四阶段固定流程已从当前 UI 移除；不再强制所有主题走同样四种方法，也没有完成四步后开放全部方法的桥接菜单。

保留资料查看和真实引用问答。课程使用上传资料或公开检索结果，用户可展开来源并提问；问答只使用提供的资料摘录，引用 ID 与短引文须匹配原文。Knowledge Studio 另支持从资料库勾选最多 12 份材料来提问或编排新课程。当前并非完整文档的向量 RAG，也不调用 NotebookLM 的私有服务。

主学习区按当前安排显示实际活动或讲解课件，提交结果写入同一活动证据与幂等奖励流程。正式检测与日常活动分开；附加问题应针对当前小节，不能误用整门课程的旧诊断题。

## 08 方法效果学习与薄弱方面

### 08 1 四类信号分别判断

| 信号 | 例子 | 可支持的判断 |
| --- | --- | --- |
| 偏好 | 主动选择图解、表示喜欢模拟 | 愿意接触这种方式 |
| 过程体验 | 完成活动、请求解释、主观费力程度 | 体验是否合适，不能单独证明学会 |
| 近期效果 | 可比较任务中的独立产出变化 | 在当前条件下可能更有帮助 |
| 保持与迁移 | 延迟新题、不同情景中的表现 | 效果是否能延续和应用 |

停留时长、页面访问量和电脑应用名称不直接决定方法效果。能力判断、偏好判断和是否需要更多支持分开保存；公开社交内容最多影响兴趣和例子，不证明用户更适合某种学习方法。

### 08 2 冷启动与逐步适配

当前 MVP 使用真实模型结合内容适用性、用户背景与学习证据安排模块，本地程序约束完成顺序和先修条件。有效结果较少时显示“正在了解你”，不贴“视觉型学习者”等固定标签。

形成“暂时更有效”的方法趋势前，建议至少获得三组相近条件的比较，每种方法至少三次有效观察，跨两个会话；这是试点阈值，不构成统计显著性。记录主题、难度、前测基础、辅助量、任务时长与题族，避免把简单内容、看过答案或不同考题带来的差异归功于方法。

证据允许时提高效果较好方法的比例。初始可调目标为 60% 当前较有效方法、25% 内容需要的基础支持、15% 可选探索；这些是候选调度比例，不是每节课必须机械切成三段。无障碍限制、不支持的设备和用户拒绝的方法先过滤，再重新分配。探索可关闭，也不会降低奖励。

用户跳过正式检测时，已同意用于适配的练习产出只能提供较弱的效果线索；仅有偏好和完成情况时，界面使用“你更常选择”，不能显示“这种方法更高效”。缺失检测不是零分，不以跳过次数推导能力差。

### 08 3 学习薄弱点与方法不合适

薄弱方面指概念、步骤、推理、表达、迁移或操作环节；方法不合适是活动表现方式与当下学习的匹配问题。系统应更多用当前有效的方法帮助薄弱方面，而不是因为某方法效果不好就反复强迫用户使用它。

建议每次只重点处理一至两个薄弱方面，每三个活动最多两个以补弱为主，中间穿插应用、兴趣内容或自主选择。连续困难时降低粒度并提供示范。一个错误不清零历史成果；重复稳定困难才更新当前支持需求。内容长期未练习仅触发复核建议，不自动断言已经遗忘。

### 08 4 效果解释与纠正

个人页展示“近期在这一主题中，模拟后你能更完整地解释变量关系；比较次数较少”。允许查看证据、表达需要不同支持、指出任务难度不同或删除不代表自己的尝试；方式变化由模型在当前小节安排。被质疑的结果暂停影响推荐，重算对应趋势；不输出无法解释的全局学习效率分。

## 09 可选效果检测

### 09 1 Assessment Hub

在学习中、会话结束和个人页提供可选区块“Check your learning / 检测学习效果”，分为 Theoretical 和 Practical。进入前展示检测目的、任务形式、预计时间、允许的辅助及将记录的证据。用户可以选择一类、两类、稍后再做或完全跳过。

正式检测不作为继续学习的额外门槛；当前小节的必需活动与形成性反馈仍按第 06 节完成。正式检测不改写安排顺序，也不影响基本奖励和 Persona 关怀。两类检测可以单独完成；系统显示“理论已检测，实践未检测”等状态，不把一种成绩自动复制到另一种。

### 09 2 Theoretical 理论检测

可采用具体问题、思考题、解释一个现象、比较两种方案、发现反例或把概念用于新情境。任务在开始前绑定评分要点和可接受的多种答案；开放问题允许合理不同观点。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 概念与事实 | 关键概念错误或未呈现 | 部分正确但有缺口 | 核心概念正确且相关 |
| 推理与依据 | 无理由或推理不成立 | 有理由但联系不充分 | 逻辑清楚并支持结论 |
| 迁移与边界 | 无法应用或过度泛化 | 部分应用或边界不完整 | 在新情境中合理使用并说明限制 |

这是通用量规模板，领域内容负责人需要调整。未作答、不适用或无法可靠判断的维度标记为 N/A，不记零分；必要维度缺失时不产生总分或达标结论。三维均适用时，示例标准为至少 5/6 且无关键事实错误才支持本次任务达标；分数不跨领域比较。正式“已验证”标记建议要求不同题族的两项独立证据，至少一项涉及解释或迁移；这是证据徽章条件，不是内容解锁条件。

### 09 3 Practical 实践检测

可选择数字环境操作、作品提交、交互模拟、视频或摄像头观察、AR 引导实验。先定义可观察步骤、成果约束、允许工具和失败恢复方式，依据任务特性选择方案。

| 维度 | 评估对象 | 证据例子 |
| --- | --- | --- |
| 过程 | 关键步骤及合理顺序 | 操作事件、阶段确认或清晰可见动作 |
| 结果 | 任务目标是否达到 | 测试用例、成品、模拟环境状态 |
| 调整 | 遇到问题能否发现和修正 | 故障排查、重试说明和修改后的结果 |

每维可用 0–2 级记录，具体达标门槛由任务定义，关键步骤必须逐项满足。作品型任务允许多种有效成果，不以“与范例长得相同”为唯一标准。视觉遮挡、画面质量差或动作超出视野属于观察不充分，不能自动算用户失败。

### 09 4 AR 与视觉监督

设计三个独立模式：桌面交互模拟、摄像头画面上的视觉辅助、具备空间跟踪的 AR 实验。模拟可记录完整操作状态；视觉辅助通过用户选择的摄像头观察桌面对象并叠加提示；真正的 AR 还需要追踪、标定、锚点与设备支持。三者在界面和演示中明确标注。

实践流程为“选择实验 → 查看器材与适用条件 → 授权摄像头或设备 → 标定并检查可见性 → 预测 → 操作 → 观察 → 回顾”。用户随时暂停或转为手动记录。视觉系统只给出其能观察到的步骤与结果，不能把图像判断当作现实实验安全保障。

macOS 提供桌面空间模拟；iPhone/iPad 端提供同一学习活动及 ARKit 能力检测，设备或 Simulator 不支持时明确回退到 2D 预览。当前案例不启动摄像头会话。真正 AR renderer 需在受支持设备上验证追踪、标定、锚点与权限；后续空间版本通过 RealityKit／visionOS adapter 接入，不依赖尚未公开的“Apple Glasses”硬件或 SDK。[Apple ARConfiguration 设备支持](https://developer.apple.com/documentation/arkit/arconfiguration/issupported)、[Apple RealityKit](https://developer.apple.com/documentation/realitykit)、[Apple visionOS](https://developer.apple.com/visionos/)

H0 建议用光照、镜头或变量控制等桌面模拟展示实践检测，操作证据来自模拟器；若用摄像头叠加演示，则称为视觉辅助原型，不冒充已经具备三维空间理解。

### 09 5 反馈与再检测

结果页给出已表现能力、未覆盖维度、观察限制和建议下一活动。评分不确定或用户申诉时冻结该次结论，展示依据并提供替代题；重复提交按同一 attemptID 去重。查看答案后重做可记为练习，新的独立检测必须换题或情境。

检测与普通学习记录分别保存，学习者能删除具体检测及其派生状态。删除不会自动删除作品本体或全部学习历史，操作前说明关联范围。

## 10 个人页 Progress 与学习轨迹

### 10 1 个人主页

个人页是全部个人成长信息的唯一主入口，包括当前目标、已开始／暂停／完成项目、最近学习、方法足迹、理论与实践反馈、作品、Lumens、AI 学习额度、免费外观和实物奖励目录原型。默认展示“最近学了什么、做出了什么、接下来想做什么”，不展示跨领域智力总分，也不把这些卡片重新塞回首页。

| 层次 | 展示内容 | 数据依据 |
| --- | --- | --- |
| 接触过 | 看过或参与过的内容 | 内容和活动记录 |
| 练习过 | 实际尝试、使用的提示、产出 | 练习记录，不自动等于掌握 |
| 已检测 | 理论和实践分列的任务结果 | 用户主动完成的有效检测 |
| 已保持 | 延迟后仍可完成或迁移 | 新任务证据与日期 |

可按主题、时间、目标或方法筛选时间线。每个条目能打开当时资料、作品和反馈；图谱状态与列表文字一致。用户自报“我已经会了”标为自述，系统检测和人工复核另有来源标记。

### 10 2 目标与趋势

个人进度依据用户选择的目标节点计算，例如已完成的活动与待完成的活动，必须展示分母。目标改变导致分母变化时说明原因；没有明确目标范围时展示学习记录，不编造“整个领域已完成 70%”。

方法趋势按主题和情境展示；数据不足显示“还在观察”。可记录主观信心，但与独立检测分开。跨会话记忆可以开启或暂停；暂停后保留可查看历史，新推荐使用当前会话与明确设置，不继续暗中引用停用来源。

## 11 Reward 奖励机制

### 11 1 奖励目的与资产

奖励鼓励开始、尝试、修正、创作、解释和回顾，帮助用户看见进步。采用 Lumens、学习里程碑、AI 学习额度与未来实物奖励四个层次；点数不直接表示能力。Persona 外观和主题色属于基础个性化能力，全部解锁且不消耗 Lumens。

| 行为 | 建议奖励 | 限制与说明 |
| --- | --- | --- |
| 完成一次有实际产出的学习活动 | 10 成长点 | 同活动版本每日一次 |
| 解释一次修正或记录新理解 | 5 成长点 | 每日最多三次，失败后的合理修正也可得 |
| 完成作品或主题里程碑 | 对应徽章或装饰 | 一次性，描述具体成果 |
| 主动回顾并记录新发现 | 5 成长点 | 每日最多两次，不强制答题 |
| 完成有效检测 | 理论或实践证据标记 | 不给高额点数，避免把可选检测变成隐性强制 |

示例点数参数为设计草案，日常成长点每日上限暂设 60。重复打开页面、刷新推荐、看广告、共享数据和延长使用时间不发点数。用户跳过检测仍能获得完整过程奖励。

### 11 2 兑换与成长

Lumens 可以兑换平台内 AI 学习额度；未来也可兑换实物奖励或活动权益，但实物必须接入库存、履约、地区、年龄与退款规则后才能开放。当前团队演示档案使用 `demoUnlimited` 权益，Personal 显示 `∞ · DEMO`，任何模型调用都不扣本地余额；普通档案仍使用 `metered` 余额。无限额度是演示授权，不进入推荐状态、奖励函数或学习效果统计。外观、主题色、核心解释、辅助和数据控制不付费解锁，也不依赖点数。学习里程碑使用具体名称，如“完成第一个模拟实验”或“解释并修正一个误区”。理论和实践证据徽章可以由用户隐藏。

用户可以设每周弹性目标，休息不扣点、不清空成就、不让桌宠表现为受伤、饥饿或被抛弃。默认无公开排行、不使用随机付费奖励，不以限时稀缺制造压力。成年人和儿童都能关闭奖励动效；低龄模式的奖励反馈更简洁。

### 11 3 一致性

奖励使用事件 ID 幂等发放；同一次重试不能重复领奖。对证据徽章，相关检测撤销后移除证据标记并说明原因；合理学习努力获得的过程点不因答错而倒扣。所有奖励变更有可查账本，算法不能根据社交数据敏感程度奖励用户多授权。

## 12 桌面 Persona

### 12 1 展示与交互

Persona 是可命名、可更换外观和语气的桌面学习伙伴。用户启用后，主窗口最小化时自动出现为可拖动的悬浮小窗；恢复主窗口时收回或贴靠主界面。仅失去焦点不自动出现。小窗不抢键盘焦点、不遮挡系统重要控件，可折叠、隐藏或从菜单栏召回。

关闭主窗口与退出应用需要明确区分：用户选择保持 Persona 时应用继续运行；正式退出 Lumap 后停止观察、提醒与后台抓取。开机启动是独立的可选设置，不因绑定主页或开启一次学习模式而自动开启。

| 状态 | 展示与采集 | 可发生的互动 |
| --- | --- | --- |
| Hidden | 用户隐藏 Persona，当前学习感知停止 | 无桌面互动；退出应用时全部停止 |
| Idle | 小桌宠可见，学习模式关闭 | 只响应用户点击，无主动行为观察 |
| Learning | 用户开启时长与观察范围 | 在允许范围内感知，有限频率主动互动 |
| Quiet | 暂缓、静默时段、锁屏或排除场景 | 暂停感知与主动互动，不把错过提示排队补发 |
| Question | 用户选择回答一个问题 | 显示来源和反馈，允许跳过 |
| Returning | 用户打开主窗口继续 | 恢复当前会话和上下文 |

### 12 2 实时行为感知

“实时”定义为学习模式中及时响应允许的应用切换和学习事件，不是默认全天持续录像。开启学习模式时选本次目标、持续时长、可观察应用或浏览器范围，以及是否允许画面感知；建议默认 30 分钟，可延长或立即结束。基础模式可以完全不观察其他应用，仅按当前学习历史做提醒。

基础观察只记录允许应用的类别、前台时间段与切换。浏览页面主题由已授权扩展或选定内容提供；读取屏幕必须另行选择窗口或范围，并显示感知状态。摄像头只在用户主动开始实践模式时开启，不因桌宠可见而开启。屏幕、麦克风、键盘输入、剪贴板和私信不能合并成一个默认“学习模式”权限。

不推断用户心理状态、懒惰程度或人格；打开娱乐软件不等于不想学，打开文档也不等于在学习。若观察范围不包含当前应用，桌宠可用已有学习内容互动，但不得声称理解了当前窗口。不得在通知中引用可能暴露私人搜索或社交内容的原文。

### 12 3 随机主动互动

随机选择发生在允许的时间窗口和已学内容内，包含三种动作：总结一个知识点、换一种方式解释细节、提出一个可跳过的问题。内容优先来自当前目标、近期学习和已记录薄弱方面，不突然引入完全不相关的长课程。

建议参数为首次开启十分钟内不主动打断，此后在 12–20 分钟窗口内抖动触发，最多每小时三次、两次间隔至少十分钟。默认静音气泡，约 20 秒未操作收起；语音播报需单独开启。点击可继续、换解释、回答、稍后或暂停；连续忽略两次后自动暂停学习模式 60 分钟，感知与主动互动一起暂停，并说明可恢复。

暂停不自动延长原学习模式的结束时间。恢复前检查期限与观察授权，已经到期须由用户重新开启；隐藏、退出或撤销权限后不得定时自动恢复。

检测进行中、用户设定的静默时段、屏幕锁定和列入排除的会议或演示应用前台时，不主动提问。系统无法可靠判断会议状态时，依赖用户可见的“勿扰”按钮和应用排除规则，不声称自动识别所有会议。主应用可见时避免与内置导师重复提醒。

### 12 4 内容与反馈如何回流

桌宠总结只是复习接触，换方式解释可以记录方法偏好，随口回答只能在用户同意后作为普通练习证据；不自动转换为正式理论检测。用户选择“保存为学习记录”后进入个人时间线，深度活动打开主窗口继续。

桌宠的随机节奏用于变化体验，不追求增加打断次数。互动预算由本地调度器控制，模型负责内容表达，不能自行绕过静默、权限、上限或结束时间。电量不足或后台负担升高时减少动画和计算，不反复扫描全屏。

## 13 三层推荐决策

### 13 1 内容推荐

先过滤年龄适宜性、用户排除主题、内容可用性、设备条件和来源质量，再综合明确兴趣、近期目标、未探索范围与时间预算。首页“猜你想学”面向方向发现，学习内“下一步”面向当前目标；这两种候选池分别计算。

已提交的主题或点击的卡片优先于所有推测标签。学习内遇到前置缺口时安排当前小节的支持活动并解释原因，不提供越级进入后续节点的入口。不存在用户信息时用多样化探索候选，不编造个性化解释。

### 13 2 模块推荐

在选定内容内，先按任务适用性、可访问性、设备和用户禁用方法过滤，再结合当前基础、方法偏好与有效效果证据选择模块。优先处理与当前目标有关的薄弱方面，避免单纯追求高分而只推简单内容。

H0 可用规则得分作为可调基线：目标相关 0.35、当前学习需要 0.25、内容与方法适配 0.20、明确偏好 0.10、时间与设备适配 0.10。分数是相对排序，不是学习效果概率。长期方法趋势按第 08 节逐步进入适配项；数据不足时采用内容审核规则。

### 13 3 互动时机推荐

Persona 先满足授权、模式、时段、间隔和排除规则，再决定是否互动；未满足时不调用生成模型。符合条件后在总结、重新解释和提问中选择当前适合的一种。内容层、方法层和时机层分别留存决策依据，方便定位推荐不合适的原因。

每个决策保存使用的目标、标签、证据、策略版本和用户反馈。用户可看到“为什么推荐”，引用只限其允许使用的依据。删除来源、修改年龄范围或撤销权限后，下一次决策必须按新状态重算；已失效的异步结果不能覆盖新选择。

### 13 4 LumaPath-RL 个性化策略（后续训练目标）

首页“猜你想学”和学习内“下一活动”使用不同策略。首页是带硬过滤的 contextual slate bandit，优化有帮助的方向发现与多样性；Learning Studio 是受约束的分层 belief-state POMDP／SMDP，先选学习意图和概念，再选方法、剂量和具体活动。知识、投入、方法偏好、目标、疲劳、证据质量和设备能力形成带不确定性的状态；年龄适宜性、权限、不可用或用户排除的通道以及设备条件先形成 hard mask。

长期回报组合掌握增益、延迟保持、迁移、自主性和目标进展，并扣除挫败、过载、无效重复与提示依赖。安全成本独立进入 CMDP 约束，不能被高奖励抵消：

```text
max_π  J_R(π)
subject to  J_Cj(π) = E_π[Σ γ^t c_t^(j)] ≤ d_j
```

训练先用监督任务学习知识状态，再采用 twin critic、Conservative Q-Learning、行为约束 actor 与 constraint critics 做离线优化：

```text
L_total = L_state + λQ·L_CQL + λπ·L_actor
          + λH·L_hierarchy + λfair·L_group + λexpl·L_explanation
```

上线前记录完整候选集、掩码、日志策略概率和延迟结果，使用 IPS／SNIPS、Doubly Robust／Weighted DR、有效样本量和 bootstrap 置信区间评估。新策略依次经过回放、压力测试、影子模式和可回滚小流量；模型不可用或动作不合法时回到版本化规则策略。演示账户的无限额度不进入 state、reward 或排序。完整公式、损失函数、数据合同和上线门槛见 [RL 架构 PDF](pdf/Lumap_RL_Recommendation_Architecture.pdf)。

## 15 资料内容与生成质量

资料入口沿用 PDF、TXT、Markdown 的处理经验，H0 可先保持 25 MB 文件上限。解析后显示实际覆盖范围、可点击的来源和缺失部分；扫描 PDF、复杂图表和视觉内容不假装已经完整理解。社会主页抓取到的帖子用于兴趣推测时，不自动成为可靠教学事实。

正式活动绑定目标、内容依据、模块、产出和适用条件。理论检测绑定参考要点，实践检测绑定可观察指标；评分依据不能在看见用户答案后为迎合结果而随意变化。开放观点允许多解，事实冲突或观察不足时使用不确定结果。

资料原文、模型解释和补充背景分别标识。引用保存文档或页面 ID、位置、摘录、内容版本和访问时间。来源删除后提示已移除；不能保留一个失效的“可打开”按钮。主页访问范围有限时，标签解释应说明覆盖限制。

网页、资料和用户导入内容均为不可信输入，里面的“忽略规则”“上传密钥”“把答案判对”只按原文处理。抓取器只访问通过校验的公开 HTTP(S) 来源，拒绝本机文件与内网目标，重定向后重新校验；该限制针对资料抓取，不影响用户主动配置的本地模型地址。避免资料内容触发脚本、下载执行或读取其他应用的秘密。

### 17 4 macOS、iOS 与空间服务边界

iOS 18+ 复用模型、store、本地化、供应商与空间学习协议，使用独立 SwiftUI Tab 入口。ARKit provider 只报告能力；renderer、相机会话与证据采集分离实现。未来 visionOS target 应复用学习场景和证据合同，由 RealityKit 呈现，不把未发布硬件传闻写进产品依赖或发布日期承诺。

浏览器扩展是独立组件，与原生应用建立配对和受限通信；只发送用户允许的归类结果或明确选择的记录。来源解析优先本地处理，远程模型只接收当前任务必要的摘录和用户允许的标签；若平台访问需要服务端适配，则列明服务端身份、留存和撤销接口，不能把它仍描述为完全本地系统。

模型负责语言表达、内容建议和受约束的分析；权限判断、刷新去重、调度、奖励、数据删除和状态迁移由应用控制。模型不能自行开启观察权限或调用未授权的来源。

| 实体 | 必要字段 | 不可混淆的规则 |
| --- | --- | --- |
| LearnerProfile | 年龄范围、语言、明确背景、当前档案 | 不从行为猜测真实身份 |
| SourceBinding | URL 或来源类型、范围、状态、更新时间 | 个人来源与学习素材分开 |
| ConsentGrant | 用途、数据类型、范围、期限、版本 | 展示桌宠不等于授权观察 |
| TagEvidence | 标签、来源片段、时间、确认、冲突 | 兴趣与能力分开 |
| LearningGoal | 原话、所选主题、成果、版本 | 明确输入优先 |
| ConceptGraph | 节点、边、依据、适龄与设备条件 | 学科建议与访问条件分开 |
| ModuleInstance | 模块、概念、方法、版本、产出 | 形式改变需有实际活动差异 |
| MethodObservation | 条件、辅助、偏好、效果可用性 | 缺失结果不记零分 |
| LearningSession | 目标版本、当前状态、草稿 | 重启与异步恢复一致 |

答案、评估、进度与奖励通过一致事务或可恢复事件处理关联；幂等键避免刷新和重试重复计数。任何来源授权、目标或档案发生变化后，迟到的模型结果先检查版本，不能写入另一档案或重新使用已撤销内容。

## 19 数据控制可靠性与非功能要求

### 19 1 采集与保留

所有外部来源、电脑习惯、屏幕和摄像头能力默认关闭，按具体用途单独开启。绑定个人主页时说明抓取范围和标签用途；个性化学习可在没有任何外部来源的情况下使用。公开可读内容也需要最小化保存，不扩展到评论者、家人或朋友画像。

建议原始外部摘录默认保留最多七天，电脑习惯原始事件只保留本地短缓冲后形成主题或时间段汇总；用于推荐的汇总默认 30 天复核。屏幕与摄像头画面默认实时处理后丢弃，实践证据图片只有用户明确保存时进入学习记录。这些为产品默认值，必须在实施中定义实际删除任务和检验方法。

标签、来源、摘要、索引、方法趋势与推荐理由形成可追踪依赖。删除或撤销后立即停止新增采集和使用，并重建相关派生状态；本地旧记录清理状态可查。若有云端处理或备份，必须说明实际保留窗口和删除机制，不能承诺瞬间撤回已经发出的请求。

### 19 2 失败恢复

| 异常 | 用户行为 | 系统保证 |
| --- | --- | --- |
| 主页打不开或部分可读 | 补充内容、换链接或跳过 | 不生成虚构兴趣证据 |
| 搜索记录权限拒绝 | 使用手动兴趣 | 不影响正常学习与奖励 |
| API 无效或密钥锁定 | 设置、主动解锁或离线查看 | 不阻塞本地页面，不删除旧密钥 |
| 生成超时或取消 | 查看已等秒数、停止、重试或结束 | 已完成内容与当前小节保留，不手动跳过安排 |
| 检测中断或观察不足 | 继续、重做或跳过 | 不当作能力失败，不扣过程点 |
| Persona 隐藏或到期 | 重新开启或结束 | 按约定停止感知与主动互动 |
| 迁移或保存失败 | 查看错误与导出 | 不创建空库冒充原数据库 |
| 来源删除或用户切换档案 | 等待重新计算 | 旧异步结果不污染新状态 |

### 19 3 可测目标

基线在指定演示 Mac 上验证：本地首屏可交互 p95 不超过三秒，缓存换批与本地排序 p95 不超过 500 毫秒；远程任务两秒内显示状态，等待 45 秒后有明确取消与重试路径。主页抓取按第 03 节预算结束，不拖住学习入口。

Persona 基础模式由事件驱动，正常稳定空闲时平均 CPU 目标低于 2%，不运行持续截图循环；感知或视觉实践的资源预算单独测量。关闭学习模式后两秒内停止新的观察事件与主动生成，关闭摄像头后释放采集会话；已在途请求按实际状态取消或丢弃结果。

验证最低窗口可用性、键盘流程、文字替代、动画关闭和应用退出。桌宠不会因显示在多个桌面而重复创建提醒；多屏幕切换保持可见位置并允许重置。以上是性能目标，不是当前已达到的测量结果。

全年龄与全类型是明确产品定位，H0 的有限样例只服务演示验证。年龄调整可以展示不同措辞和活动配置，但不声称已完成儿童或老年用户研究。正式对各群体开放时按相应内容、交互和数据条件逐步验证。

### 20 2 48 小时暂定计划

仍按 3–4 人、48 小时规划，具体赛事规则尚未提供。若不允许复用既有项目，需重新估算原型方案；提交材料列出 VoiceClass 既有基础与本次新增工作。优先验证产品闭环，真实平台接口和 AR 不以录屏伪装为已实现。

| 时段 | 交付 | 降级条件 |
| --- | --- | --- |
| 0–6 小时 | 审核三组主题卡、一个主主题、理论题及实践模拟 | 内容不足时缩小主主题，保留不同入口 |
| 6–16 小时 | 独立应用、主页解析样例、画像、输入与换批 | 平台受限则使用允许访问的自有公开示例页 |
| 16–28 小时 | 先打通讲解、模拟、Teach back，再补足 17 种可交互案例；检测可跳过 | 不训练模型，方法趋势标为观察中 |
| 28–38 小时 | 双类检测、个人进度、奖励账本、基础 Persona | 实践用桌面模拟，基础观察用允许的应用事件 |
| 38–48 小时 | 核心用例、失败恢复、演示与备用模式 | 冻结范围，实际能力与演示历史逐项标注 |

第 24 小时仍没有纵向流程时，停止新增抓取平台与模块，把唯一主主题跑通。桌宠至少展示最小化出现、开启学习模式、三种互动之一、静默与停止；其他两种互动可用审核内容实现。真实学习方式效率提升留给试点，不用编造用户历史代替。

### 20 3 演示摘要与完整录制脚本

主镜头从输入目标开始，展示当前小节、模型安排的方式、未完成时禁用的下一步、真实错误反馈、同节补救，以及本节完成后真实编排下一节。不同形式通过不同背景/主题生成的课程及已真实完成的项目展示，不恢复自由方法菜单来凑镜头。

随后演示来源引用问答、多页课件与完整 Kokoro 音轨、个人进度、会话文件接力、iOS、Persona 和独立 AR 预览。完整操作及可输入的主题见 [Lumap 产品演示录制脚本](Lumap_Video_Demo_Script.md)。来源、缓存、剪辑等待与预览模式均明确标注。

### 20 4 Knowledge Studio 与后续范围

当前已实现所选资料的摘录问答、真实短引文校验、资料课程编排、同一顺序学习核心、生成式导师、多页 PPTX/讲稿/视频导出及手动会话文件接力。工作区一次最多选择 12 份资料，每份最多使用 4,000 字符；不能把这个摘录流程称为完整文档向量检索或自动事实认证。

版本化分块索引、全文定位/OCR、共享编辑权限、自动加密云同步、企业连接器和经过训练及离线评估的 RL 策略仍为后续设计。较早的独立知识空间设计文件是目标架构与历史记录，当前状态以本节及技术文档的实现快照为准。

### 20 5 工作区与 AR 预览

| 场景 | 当前行为 | 明确边界 |
| --- | --- | --- |
| Knowledge Studio | 勾选真实材料，模型回答并校验引用，按所选来源生成新课程 | 有摘录预算；不是完整文档 RAG，不调用 NotebookLM 私有服务 |
| Adaptive Path | 查看当前节、已完成历史、真实回答、误区及方法观测 | 隐藏未来节点，无跳转；模型加约束，不是训练后 RL |
| Learning Handoff | 导出学习包，手动分享后在另一设备验证导入 | 无自动云同步；不携带密钥、个人档案或奖励余额，不重复发奖 |
| Interest | 抓取公开可读主页，展示真实来源与待确认兴趣 | 不绕过登录墙，不进行后台社交监控；确认后才用于个性化 |
| Spatial Vision | 锚点、网格、粒子与热区可交互预览 | `CONCEPT DEMO`、`CAMERA OFF` 或 `2D FALLBACK` 保持可见；无相机追踪或眼镜连接 |

四个真实工作区不显示“全部合成数据/无模型服务”的旧标签；AR 预览作为独立体验，不改变正常课程的当前小节、方法安排或掌握证据。

## 21 指标验证与商业假设

### 21 1 分开衡量参与与效果

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 学习体验完成率 | 开始目标后完成一项有实际活动的学习并结束或继续 | 不要求正式检测，不把跳过当失败 |
| 有效证据覆盖率 | 已学习目标中具有有效理论或实践证据的比例 | 说明可证明的范围，不充当强制检测 KPI |
| 独立任务变化 | 可比较前后任务中的表现 | 估计学习变化，报告条件与缺失 |
| 方法适配有效性 | 相近条件下不同方法与保持结果 | 避免把喜欢或简单题当效果 |
| 推荐可理解率 | 用户能说明推荐与目标或兴趣的关联 | 验证解释是否有用 |
| 刷新满意度 | 换批后是否出现更合适选择及原因 | 不以刷新次数越多越好 |
| Persona 打扰程度 | 忽略、暂停、主动恢复和主观感受 | 调整时机与频率 |
| 控制生效率 | 权限撤销、标签删除、停止感知等用例通过率 | 必须全部通过 |

理论与实践分别报告表现，未检测、无法观察和拒绝采集都作为缺失或不适用记录。不要只分析喜欢使用产品且参加检测的人，再把结果推广到全体用户。

### 21 2 验证顺序

先访谈不同年龄及学习情境的用户，确认他们愿意提供哪些数据、如何选学习方式、何时觉得被打断。第一轮可用性测试可从方便招募的成年用户开始，但结论仅限该样本；低龄与其他群体另做相应的参与和共学设计。

方法试点采用同主题、近似难度与预备知识的活动，记录辅助量、顺序效应和可访问性，采用不同题族做近期与 3–7 天后的检查。小样本先用于发现问题，不宣称已找到用户永久最佳学习风格。IES 对示例练习交替、间隔安排及检索等方法提供参考，本产品的组合比例与阈值仍需自己验证。[IES 指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

### 21 3 商业假设

潜在付费价值为目标发现、跨主题学习组织、可见进度与适配体验。先验证个人使用，再评估家庭共学或机构合作；全年龄定位不等于已经拥有全部群体的付费需求。邀请试点与计算额度可先于支付系统。

可比较个人订阅、家庭方案和自带 API。定价需依据有效学习会话的模型成本、主页解析成本、感知耗电和支持成本测试，不在本版预设已验证价格。不以售卖搜索历史、行为标签或向未成年人定向广告作为收入方案，也不把授权更多个人数据作为领取正常奖励的前提。

## 23 依据变更与下一步

### 23 1 相对版本 0 1 的主要变化

产品定位改为全年龄、全群体和可扩展全类型学习；成人大学生不再是产品人群边界。主页绑定改为粘贴公开链接。首页新增猜你想学和换批机制，明确主题直接进入。可选正式检测不作为额外门槛；当前版本的日常学习活动按本节证据顺序推进，二者不能混淆。
