# Lumap 产品需求文档

启发式个性化学习软件

版本 0.1　｜　2026 年 9 月 29 日　｜　状态：产品设计草案

面向 Lumap 创始团队、设计与开发成员，以及墨尔本大学 Hackathon 项目讨论。本文定义产品愿景、首版体验、推荐与学习机制、工程边界和验收方法；涉及效果、商业收入、算法参数和开发周期的数字均为设计目标或待验证假设，并非已有结果。

**建议决策：** 首版让用户从一句模糊的学习意愿出发，在一次约 10–15 分钟的学习中确认方向、完成一个可检查的任务，并看见下一步为何发生变化。产品长期积累应用内学习证据，逐步形成用户可以检查和纠正的个人学习地图。Hackathon 先用一个经过人工审核的知识领域证明这一闭环。

本次交付只建立 `Lumap` 独立子目录及 PRD。后续开发沿用现有项目的技术能力，但 Lumap 应拥有独立名称、应用身份、数据存储和学习体验。

## 01 产品定义与价值主张

### 01 1 产品要解决的问题

学习者经常只能表达“想了解 AI”“想看懂这篇论文”，很难同时说清真实动机、已有基础、需要达到的程度，以及下一步应该学什么。即使拿到一份课程清单，也可能因为缺少前置知识、任务过大或兴趣变化而中断。现有 VoiceClass 能帮助保存和理解资料，但尚未管理从目标探索到学习证据再到路径调整的持续过程。

Lumap 的核心对象是“下一次有意义的学习行动”。它把用户的意图视为可修订的目标假设，先用短互动和实际任务找到起点，再结合知识依赖、学习表现和用户选择，提出一个有理由的下一步。

**一句话定位：** Lumap 是一个通过对话发现方向、通过任务了解掌握情况、通过学习地图持续调整路径的 AI 学习伙伴。

英文产品介绍建议使用：Lumap helps you discover what to learn, build the foundations, and choose your next step through guided practice.

### 01 2 产品承诺

- 允许从“不知道想学什么”开始，尽快得到一个可尝试的小任务。
- 把基础、目标和拓展的关系解释清楚；已有基础可通过挑战题证明。
- 根据真实学习证据调整任务难度、例子和路径，同时允许用户改变选择。
- 明确区分已经观察到的表现、用户主动说明的偏好和系统的暂时推测。
- 保留长期学习轨迹，让用户知道自己已经能做什么，以及哪些结论仍需验证。

“完全颠覆现有学习模式”属于团队愿景。当前不能据此宣称市场上没有类似能力。Khanmigo 官方已介绍引导式学习与批判性思考能力；Lumap 应验证的差异点是“模糊意图发现、可解释路径变化、长期证据和用户纠正”是否形成更有价值的组合。[Khanmigo 官方介绍](https://www.khanmigo.ai/)

### 01 3 成功应被如何理解

用户能更清楚地说明当前学习目标，独立完成此前不能完成的任务，并理解下一步建议。停留时间、连续登录和对角色的喜爱可以用于体验诊断，但不作为学习成功的替代指标。

## 02 用户与关键场景

### 02 1 首版用户假设

首版暂定面向 18 岁及以上大学生，尤其是正在接触陌生课程、跨专业主题或英文资料的自主学习者。此选择便于在大学 Hackathon 环境开展小规模验证，不代表产品长期仅服务成年人。暂不依赖学校账号、课程管理系统或教师后台。

| 用户类型 | 典型表达 | 主要困难 | Lumap 应交付的结果 |
| --- | --- | --- | --- |
| 方向不明确的探索者 | 我对 AI 有点兴趣，但不知道学什么 | 无法把兴趣变成可执行目标 | 三个以内的方向及一次探索任务 |
| 带资料来的学习者 | 我想看懂这份讲义 | 不知道自己缺哪些基础 | 资料目标、前置缺口与短学习路径 |
| 目标明确的学习者 | 我明天要解释模型准确率 | 时间有限，不想重复已经会的内容 | 起点挑战、精简路径和独立任务 |
| 长期返回的学习者 | 接着上次学，但换个应用方向 | 历史散落，兴趣与目标会变化 | 可延续的证据、目标修订与新分支 |

这些画像是设计假设，不是已经完成的访谈结论。

### 02 2 低龄学习的长期设计

保留“表达能力有限也能开始”的产品原则：短句、具体场景卡片、图片选择、示例任务和“都不确定”入口。语音可以作为可选表达方式，不能把长时间录音设为画像的前提。首版先用成人用户验证这些低表达负担的交互。

未成年人公开版本需另设项目阶段，补齐年龄适配内容、监护关系、数据控制、风险处理和真实目标人群测试。系统不得根据阅读速度、拼写、语音特征或兴趣推断智力、心理状态或固定能力标签。监护者和学校也不应默认获得学习者的全部私人对话。具体规则在该阶段确定，不将当前成人原型包装成已适合儿童使用的产品。

### 02 3 核心使用任务

当我不知道如何开始时，帮我找到一个值得尝试的方向；当我遇到困难时，帮我定位缺口并给出适量支持；当我完成任务时，告诉我这说明了什么，并给我一个可以接受或修改的下一步。

## 03 范围与版本规划

### 03 1 当前约束与待确认假设

| 项目 | 当前规划 | 对范围的影响 |
| --- | --- | --- |
| 开发平台 | macOS 优先，基线沿用 macOS 14 | 不同时开发 Windows 和移动端 |
| 语言 | 界面英文默认，可切换简体中文；教学语言独立 | 提示词、评分、反馈和错误都需适配 |
| 开发条件 | 暂按 3–4 人、48 小时 | 核心领域和演示路径需严格限量 |
| 演示内容 | AI 结果与新闻可信度判断 | 六个核心节点为交付基线，12 个为扩展目标 |
| AI 接入 | 一套实际验证的模型配置，保留自定义 API 入口 | 不以支持所有供应商作为演示目标 |
| 赛事规则 | 具体赛事、日期、主题、评分标准尚未提供 | 既有代码使用规则与材料格式需核对 |

### 03 2 版本边界

| 版本 | 必须做到 | 暂不承诺 |
| --- | --- | --- |
| H0 Hackathon | 意图发现、短诊断、审核图谱、启发式学习、证据更新、可解释下一步、本地恢复 | 任意学科可靠建图、真实长期效果、儿童版本 |
| V1 用户试点 | 多份资料、跨会话偏好、到期复习、更多领域、画像编辑、可用性与学习验证 | 自动了解用户全部生活、普遍提升学习成绩 |
| V2 产品扩展 | 经验证的个性化模型、可选同步、协作场景、年龄适配版本 | 未验证的全自动教育替代方案 |

### 03 3 优先级

P0 是缺失就无法证明核心闭环的需求。P1 是闭环稳定后增强可信度和使用体验的需求。P2 是未来商业化或大规模使用需要的能力。

| 优先级 | 需求集合 |
| --- | --- |
| P0 | 独立应用与数据、英文默认、三个学习入口、目标确认、短诊断、学习地图、分级提示、检查题、推荐解释、断点恢复、基本资料导入、API 设置与失败处理 |
| P1 | 可编辑画像、延迟复习、可选导师外观、学习导出、多资料整合、图谱审核工具、评估记录 |
| P2 | 跨设备同步、教师与监护端、群体推荐训练、学校系统集成、支付和课程市场 |

H0 的资料导入限定为演示领域内的可提取文本文件；自由领域先显示“探索草案”并禁止伪装成已经审核的学习路径。角色立绘不承担推荐或掌握判断职责，不应挤占 P0 工期。

## 04 核心体验与用户旅程

### 04 1 第一次打开

首页提出一个直接的问题：“What would you like to understand?” 用户可以输入一句话、导入资料，或选择“I’m not sure yet”。无需注册、填写长问卷或先配置一整套个人档案。

准备好的演示设备可以预先配置团队自有 API。普通用户尚未配置模型时，仍能查看功能说明和明确标注的本地示例；开始在线生成前再引导设置。接口失效时不得用样例回复冒充实时生成。

### 04 2 模糊目标到第一个成果

1. 用户输入“I want to learn about AI, but I don’t know where to start.”
2. Lumap 展示最多三个具体方向，例如理解模型如何预测、判断 AI 新闻中的结论、解释模型为什么会出错；每项包含一个能完成的小任务。
3. 用户选择“判断 AI 新闻”，系统重述暂定目标：“今天先学会判断一个 95% 准确率的说法是否充分。”用户可修改或选择先探索。
4. 系统提供 2–3 个短诊断任务，包含“不知道”和“跳过”。根据答案决定是否需要补充分母、样本或测试集概念。
5. 学习地图只展开本次 3–5 个相关节点，其余内容折叠。用户看到目标、建议起点、必要基础和预计时间区间。
6. 学习中先预测，再给解释与例子，然后做新任务；遇到困难增加支持。
7. 最后提交一段简短判断，系统展示依据和仍缺少的要点，更新证据并给出下一步。

### 04 3 文件带学

用户上传 PDF、TXT 或 Markdown 后，先看到解析状态、内容预览、来源和领域匹配情况。Lumap 提出“想理解核心观点、准备讲解、完成练习”三类成果选择，允许直接修改。系统依据已审核节点匹配资料内容，标出资料涉及但未解释的基础，再进入学习。

文件是学习依据之一。缺失概念可以用经过标记的补充解释提供；不得把模型补充知识伪装成文件原文。用户可打开引用位置核对。

### 04 4 返回与方向变化

返回时显示上次目标、最后完成任务和一个建议动作。用户可以继续、复习或修改目标。修改时给出路径差异，例如保留已验证的样本概念、增加类别不平衡、暂缓精确率。过去的证据保留；旧目标不自动覆盖新目标。当前活动中不突然更换题目，更新在活动完成或用户明确切换时生效。

## 05 信息架构与关键页面

### 05 1 macOS 工作区

左侧栏提供 Today、My Map、Library、Learning History 和 Settings。学习过程中主区域用于解释和操作，右侧可折叠栏显示当前目标、概念位置、提示和资料引用。窗口较窄时右栏收为抽屉，保证题目和作答区不被压缩。

首页保留一个主行动，避免把学习变成无尽的信息流。推荐卡默认一项主建议和最多两项备选。路径用节点及关系表达，同时提供可键盘访问的列表视图。

| 页面 | 主要信息 | 主要动作 | 必须覆盖的状态 |
| --- | --- | --- | --- |
| Today | 当前目标、本次时间、下一步及原因 | 开始、换方向、导入 | 新用户、返回、无 API、无建议 |
| Goal Discovery | 用户原话、方向卡、暂定成果 | 选择、纠正、先探索 | 明确、模糊、无法匹配 |
| My Map | 核心节点、前置关系、证据状态 | 展开、挑战、预览、调整路径 | 未评估、待补充、已验证、过期待查 |
| Learning Studio | 活动、导师回应、答题、来源 | 预测、提示、解释、提交、退出 | 加载、学习、反馈、断网、已恢复 |
| Library | 本地资料、解析情况、使用范围 | 导入、查看、移除 | 空、处理中、失败、可用 |
| Learning History | 目标变更、任务证据、推荐原因 | 继续、纠正、删除、导出 | 无记录、演示记录、真实记录 |
| Settings | 语言、模型、密钥、数据管理 | 测试、授权、导出、清除 | 无密钥、锁定、失败、正常 |

### 05 2 文案与可访问性

不显示“你的能力太低”等人格化判断，使用“这个概念还没有足够证据”或“本次任务需要更多支持”。提示不是惩罚，使用提示也不扣用户积分。英文界面、教学语言和导入材料语言分别处理，中文回答不能因语言不同被判错。

所有主要操作支持键盘，焦点顺序与视觉顺序一致；颜色之外还需有状态文字。打字动画可关闭，减少动态效果时直接显示完整文本；旁白与角色内容不遮挡题目。VoiceOver 应能读出节点名称、状态、关系和按钮目的。示范窗口以 1180 × 760 为基准，最小 1000 × 680 仍可完成闭环，较小内容区通过折叠侧栏适配。

## 06 功能需求

### 06 1 意图发现与目标管理

**F01　P0　输入与澄清。** 接受自由文本、文件入口和“不确定”。澄清最多三轮，每轮只问一个影响学习决策的问题，例如想解决什么实际问题、已有接触或本次可用时间。每轮允许跳过；第三轮结束仍不明确时，提供一个约五分钟的探索活动。

**F02　P0　暂定目标。** 保存用户原话与系统重述，重述必须是可观察成果，如“能指出一个准确率声明还缺哪些证据”。用户确认后成为活动目标；明确选择“先探索”时记录为探索目标。新的推测不静默替换已确认目标。

**F03　P0　目标调整。** 用户可以修改、暂停和归档目标。更新生成新版本，并展示新增、保留、暂缓的节点。一次保持一个活动目标；其他目标可保存，避免多个方向争夺同一会话。

### 06 2 诊断与路径

**F04　P0　短诊断。** 用 2–3 个与成果相关的任务判断起点，允许选择题加一句理由、简短解释或小场景判断。不强制诊断；跳过的概念为“未评估”。用户自述“我学过”用于选择挑战题，不直接写成已掌握。

**F05　P0　学习地图。** 路径节点显示目标、前置条件、预计投入、证据状态和推荐理由。默认只突出当前节点及最近的必要关系。已验证的前置可以跳过；未知前置提供短诊断；薄弱前置优先补充。一次独立成功可跳过讲解并进入另一题族的检查；满足两项有效独立证据后，才能满足必要前置。挑战流程包含这两项检查，也可复用一项有效历史证据。

**F06　P0　用户覆盖。** 对建议不满意时可以挑战跳过、先看概览或换方向。没有足够前置证据的高级内容仍可预览，但标注“探索模式”；不能借此写入已经通过基础的结论。可随时返回补基础。

### 06 3 学习与检查

**F07　P0　启发式活动。** 活动包含明确目标、引入场景、一个关键概念、适量解释、练习和检查。系统根据任务需要选择预测、比较、自我解释、错误分析或迁移应用，不能把每一条回应都写成反问。

**F08　P0　分级支持。** 可选择概念提醒、局部示范或完整讲解。连续两次没有进展时默认增加支持，并用新题检查。“一次无进展”限定为同一节点的一次有效评分仍发现相同未解决要点，或用户主动表示无法继续；请求解释、一般提示、取消、网络失败和评分不确定不计数。独立成功或切换目标时重置计数。用户点击“Explain it”后立即进入讲解；展示完整答案后当前题的正确回答只能记为有支持完成。

**F09　P0　检查与反馈。** 题目生成时绑定概念、参考要点、题型、难度和评分规则。反馈指出覆盖要点、错误或缺失要点及下一次尝试。开放题评分不可靠时使用“不确定”，保留答案但不更新掌握结论。用户可质疑评分，质疑期间冻结该结果对画像的影响。

**F10　P0　会话总结。** 显示本次完成的任务、可支持的能力判断、未解决问题和下一步。允许结束学习，不用强制连续学习、排行榜或奖励催促继续。

### 06 4 推荐与长期记忆

**F11　P0　推荐卡。** 展示一项主推荐和最多两项备选，包含原因、时间区间和预期成果。理由必须引用真实目标、已记录证据、到期复习或已确认兴趣；没有历史时明确是探索建议。

**F12　P0　记录与恢复。** 在目标确认、有效作答、评分完成和活动结束后保存。崩溃或关闭后恢复到最近稳定状态；尚未提交的输入尽量作为本地草稿恢复。请求重试不能重复计入答题证据。H0 提供“使用历史学习证据”开关和清除学习历史入口；具体使用范围见第 09 节，完整逐项画像编辑属于 P1。

**F13　P1　画像管理。** 用户能查看“你告诉我的”“学习中观察到的”“尚待确认的”三组记录，逐项纠正、删除或限制使用范围。删除后相关摘要、向量索引和未来推荐也应移除依据。H0 的基本历史使用开关和整体清除不依赖此完整编辑页。

**F14　P1　复习。** 根据最近独立表现和用户时间安排提示复习。H0 只实现会话结束的复习建议与本地到期字段；V1 完成日历式到期管理。长期未使用只表示证据需要更新，不宣称用户已经遗忘。

### 06 5 资料与配置

**F15　P0　资料导入。** H0 支持单份 PDF、TXT、Markdown，文件上限沿用 25 MB。显示解析结果和可用内容；扫描 PDF、图片和复杂公式不假装已经理解。H0 文本路径中不可提取的文件直接给出转为可搜索 PDF 或文本的建议。

**F16　P0　语言与模型。** 英文是界面和新建学习会话的默认语言；用户可分别修改为简体中文。自定义 API 支持端点、模型和用户自己的密钥，提供测试、取消和明确错误。旧的中文固定提示词必须改造。

**F17　P1　导师外观。** 可选名称、语气、头像或立绘、背景及关闭角色展示。外观只影响表现，不改变判分与学习要求。Lumap 默认采用原创简洁视觉；现有来源不明的第三方角色素材不进入公开版本。

**F18　P1　导出与删除。** 导出学习目标、资料来源、路径及证据为 Markdown，结构化 JSON 用于数据迁移。密钥不进入导出。删除资料时明确是否同时删除依赖该资料的学习记录；仅删除资料时引用保留“来源已移除”状态，不伪造可打开的位置。

## 07 学习状态机

主流程为“发现方向 → 确认目标 → 判断起点 → 建议路径 → 学习与支持 → 检查 → 回顾 → 选择下一步”。暂停、模型失败和用户修改目标是全局可达状态。

| 状态 | 系统责任 | 转移条件 |
| --- | --- | --- |
| Discover | 提出最多三个方向，限制澄清轮次 | 用户选择或开始探索 |
| Align | 生成可修改的暂定目标 | 用户确认，或显式接受探索目标 |
| Diagnose | 收集起点证据 | 完成、跳过或发现任务不适合 |
| Plan | 给出短路径和依据 | 用户开始、挑战或改目标 |
| Learn | 提供场景、解释和活动 | 到达检查点或请求支持 |
| Support | 增加提示、示范或补基础 | 回到活动或使用新题检查 |
| Check | 按规则评估，处理不确定结果 | 有效反馈、换题或评分申诉 |
| Reflect | 展示本次证据与未解决点 | 用户结束或请求下一步 |
| Recommend | 排序候选并解释 | 接受、选择备选、暂停或改方向 |

状态变化由应用控制。模型只返回受约束的内容与建议，不能自行宣布完成所有节点、改写已确认目标或绕过证据规则。暂停时保存活动版本和题目；恢复前若配置变化，只对后续调用使用新模型，不丢弃已完成内容。

## 08 知识图谱与从宽到窄的路径

### 08 1 两种不同的范围变化

方向发现从多个可能兴趣逐步收敛到一个可执行目标；课程依赖则从必要基础走向具体应用。两者不能混为一张无限扩张的课程表。对已经熟悉基础的人，诊断后可直接进入较深节点；对兴趣变化的人，可以沿相邻应用分支重新探索。

每个节点描述一个可验证能力，边分别表示必要前置、建议前置和拓展关系。必要前置组成无环图；拓展关系可以双向关联，但不参与解锁计算。资料提取的候选节点需要去重、映射与审核，不能因为模型说“这是基础”就成为强制门槛。

### 08 2 H0 演示图谱

以下是供内容负责人审核的结构草案，不能当成已经验证的教学顺序。必要前置应由实际任务验证后固定为演示版本。

| 节点 | 可观察能力 | 前置关系 |
| --- | --- | --- |
| N01 结论与证据 | 区分一个主张和支持它的观察 | 无 |
| N02 样本与总体 | 说明少量案例为何可能不代表整体 | 无 |
| N03 特征与标签 | 指出分类任务的输入和目标 | 无 |
| N04 训练与测试 | 解释训练数据与测试数据的用途 | 必要 N03 |
| N05 准确率 | 计算并解释正确比例及分母 | 必要 N02 |
| N06 类别不平衡 | 识别全猜多数类也能高准确率 | 必要 N05 |
| N07 泛化与泄漏 | 识别测试信息进入训练的问题 | 必要 N04 与 N05 |
| N08 两类错误 | 区分漏报和误报及其代价 | 必要 N05 |
| N09 精确率与召回率 | 选择适合一个情景的指标 | 必要 N06 与 N08 |
| N10 评估准确率声明 | 指出高准确率还缺哪些上下文 | 必要 N06 与 N07；建议 N08 |
| N11 提出核实问题 | 为一条 AI 新闻列出证据需求 | 必要 N01 与 N10 |
| N12 小型评估说明 | 用结构化短文解释结果与限制 | 必要 N11；建议 N09 |

H0 基线为六个较粗粒度节点：结论与样本、分类与训练测试、准确率、类别不平衡、泛化与泄漏、评估声明。它们分别合并或对应上表中的 N01 与 N02、N03 与 N04、N05、N06、N07、N10 与 N11，并在独立的 H0 图谱版本中记录边与题目。每个核心节点至少准备两个不同题族及评分要点；N08、N09、N12 和更细粒度拆分是扩展目标。

完整图的重点演示路径为 N05 → N06 → N10 → N11；六节点版使用对应合并节点。已满足的前置通过演示档案中的明示证据或真实挑战题跳过。不得隐瞒缺失的 N07 等前置。H0 与扩展图版本不在同一会话中混用，节点拆分后的证据能否迁移需要重新核对。

### 08 3 路径变化规则

缺少必要前置时优先推荐补充或诊断。一次独立挑战成功可跳过对应讲解，进入第二个独立检查；达到已验证标准才解锁依赖它的正式任务。目标变化时重新计算相关子图，保留有效的共同节点。用户连续遇到困难时缩小任务粒度，优先补一个最相关缺口，避免突然生成几十节基础课。

图谱无可用下一节点、出现循环或关联不可靠时，退回审核路径或短探索，说明路径暂时无法生成。高级内容可以预览，但预览完成不等于前置已满足。

## 09 用户模型与记忆

### 09 1 三类模型分开保存

| 模型 | 回答的问题 | 主要来源 | 允许的用途 |
| --- | --- | --- | --- |
| 目标假设 | 此刻希望获得什么成果 | 用户原话、确认、近期任务 | 选择目标子图和完成条件 |
| 兴趣偏好 | 愿意通过什么主题或方式学习 | 主动选择、纠正，弱权重交互 | 在适合候选之间排序、选择例子 |
| 概念证据 | 能独立完成什么任务 | 作答、解释、迁移与复习 | 判断起点、支持和前置状态 |

另存每条判断的来源、时间、适用范围和是否由用户确认。“我喜欢体育例子”不意味着数学能力强；打开了十次机器学习资料也不意味着掌握机器学习。界面语言、学习语言和表达支持偏好属于设置，不应被解释成能力。

### 09 2 应用内痕迹的使用规则

H0 只记录本软件中的明确选择、任务表现、提示使用、资料引用和推荐反馈。停留时间、关闭页面、未完成活动最多用于判断当前流程是否繁琐，不直接归因于兴趣低或能力不足。不采集浏览器历史、其他软件内容、后台音频或社交账号。

V1 的长期兴趣信号按强弱分层：用户确认的偏好优先；重复主动选择形成暂定偏好；单次点击不更新长期偏好。连续两次推荐被跳过时先询问“不相关、太难、已会、现在没时间”中的原因；未回答则不推断。暂定偏好默认 30 天后要求再确认或降低影响，30 天是试点参数。

### 09 3 记忆控制

H0 保存目标、会话和任务证据以恢复当前进度。跨会话使用历史证据默认关闭，用户可以主动开启；开启后，过去有效的任务证据才参与新会话的前置判断和推荐。H0 的推测兴趣仅限当前会话，不建立持久兴趣标签；长期兴趣与逐项编辑在 V1 实现。

关闭历史使用后，新会话只使用当前目标、当前会话证据和明确设置，过去证据不能继续满足前置门槛；历史仍可查看，但本次需要短诊断或挑战。恢复同一个未结束会话属于继续当前会话，仍使用该会话内证据。已经通过跨会话证据解锁的当前活动可完成，下一次计算按新设置重新检查，避免答题中途失效。

已保存历史不因关闭开关而自动删除；H0 另提供清除学习历史入口，并先展示将删除的目标、会话、证据和派生摘要范围，资料与 API 设置独立保留。真实历史、导入历史和演示历史必须有不同来源标记。演示档案使用历史证据时也需显示开关状态。

删除一条证据后，重新计算受影响的状态和推荐解释。不能只删界面上的一句话，却仍在摘要或索引里保留同样的偏好。历史推荐可保留结构记录，但被删依据应显示已移除，并停止参与今后的计算。

## 10 推荐算法与可解释决策

### 10 1 H0 的实现选择

采用可回放的规则排序：图谱生成候选，应用负责前置约束和评分，模型负责把结构化理由转成自然语言。H0 不训练群体模型，不声称凭少量对话准确理解人格，也不把模型的自报置信度当成统计可靠性。

每次在活动完成、用户修改目标或删除相关证据后重新计算。普通文字聊天和每一次点击不都触发重排。相同状态、相同图谱版本和相同排序参数应得到一致的推荐。

### 10 2 候选生成与约束

先从当前目标子图生成四类候选：补必要前置、继续核心节点、复习已有节点、探索相邻应用。排除用户明确拒绝的非必要兴趣分支及例子主题，过滤无可用内容、来源不足和语言不支持的活动。必要概念不能因“不感兴趣”被静默删除；说明依赖后提供换例子、修改目标或探索预览。未知前置转为诊断候选，薄弱前置转为补充候选，高级任务暂不作为默认主推荐。

优先处理阻碍当前目标的关键缺口；当存在这种缺口时，主推荐从补充或诊断中选。没有关键缺口时，在其余合法候选中排序。兴趣不能把一个明显超出前置要求的活动推成默认教学任务。

### 10 3 候选评分草案

所有因子归一化为 0–1，依据由应用从结构化状态计算。下列权重是 H0 可调规则，不是训练结果，也不是对学习增益的概率预测。

| 因子 | 权重 | 计算依据 |
| --- | --- | --- |
| 当前目标相关程度 | 0.35 | 核心路径为 1，直接拓展为 0.5，其他为 0 |
| 证据支持的学习需求 | 0.25 | 已观察缺口、必要未知项或到期复习，按规则赋级 |
| 难度与前置适配 | 0.20 | 前置满足且挑战合适优先；预览内容不参与主推荐 |
| 已确认兴趣匹配 | 0.10 | 明确偏好为 1，暂定为 0.5，无依据为 0 |
| 本次可用时间匹配 | 0.10 | 能在预算内完成优先，超时任务拆小后重新候选 |

分数是五项“权重 × 因子”的和。无兴趣历史不猜测偏好；同分时依次按必要前置、目标距离、最近未重复和稳定节点编号决定。学习需求建议分级：关键薄弱项 1、关键未知项 0.8、到期复习 0.7、普通未学核心项 0.5，后续根据试点调整。

如复习任务逾期且本次时间足够，可先插入一个不超过约两分钟的复习检查；连续两次会话只探索新内容时提示回顾，用户可以忽略。主推荐之外保留一个巩固选择和一个相关应用选择，前提是确有合法候选；不为凑满三张卡生成无依据内容。

### 10 4 解释与用户纠正

推荐保存候选列表、约束结果、各项得分、使用的证据编号、参数版本和最终选择。解释以两条关键依据为主，例如：“你希望判断 AI 新闻；刚才只引用了总准确率，没有检查类别比例。先看多数类基线，能帮助你判断 95% 是否有意义。”

用户可以选择“我已经会了”“不感兴趣”“现在没时间”或“换一种方式”。已经会了转为挑战题，不直接授予掌握；不感兴趣只影响兴趣及拓展；没时间调整任务长度；换方式改变表现形式，不抹去当前概念的困难证据。

### 10 5 从 H0 到长期个性化

V1 先验证规则是否提高目标清晰度和任务完成质量，再加入时间间隔、不同领域迁移和更稳定的能力估计。只有积累了足够、获得授权且质量可控的学习事件，才评估知识追踪或上下文推荐模型。升级必须与规则基线比较，检查新用户、不同语言和不同基础群体，保留解释、回退和用户纠正能力。

## 11 教学策略与掌握证据

### 11 1 启发式教学的具体行为

一段学习采用“尝试 → 支持 → 新情境检查”。先用预测或简短解释暴露理解，随后根据表现提供概念讲解和例子，再通过不同材料检查是否能够独立应用。对于没有基础的用户，可以先看完整示例；用户要求直接解释时不继续强迫猜测。

这一设计参考了 IES 关于间隔学习、示例与练习交替、检索练习和解释性提问的建议。该来源支持教学方法的选择，不证明 Lumap 已经有效，也不为本 PRD 的具体阈值背书。[IES 学习与教学实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)

### 11 2 证据状态

| 状态 | 进入依据 | 产品行为 |
| --- | --- | --- |
| 未评估 | 无有效任务证据或主动跳过 | 提供短诊断，不推断不会 |
| 需要支持 | 本次有明确缺口，或只能在示范后完成 | 提供提示、拆分任务或补前置 |
| 初步掌握 | 一次独立任务达标 | 可跳过讲解进入第二次检查，尚不满足必要前置 |
| 已验证 | 两次不同题族的独立任务达标，至少一次解释或新情境应用 | 可满足对应前置条件，显示证据日期 |

“已验证”只表示在这些任务上得到支持，不等于永久掌握。长时间未检查时保留历史状态并加“建议复核”，不得按时间直接判定不会。H0 不向用户展示带小数的掌握百分比。

一次错误不会清零已有证据。对已经验证的节点出现新错误时，保留历史状态并标记“发现新缺口，待复核”；受该缺口影响的下一任务先做短检查。复核仍显示相同缺口时，当前状态改为需要支持，并保留变更原因。

### 11 3 有效证据规则

“独立”指检查过程中没有获得该题答案、局部解法或模型代写；可以获得不涉及答案的界面和题意澄清。允许的辅助材料应在任务中事先注明。阅读完成、追问次数、自信程度、角色互动均不构成掌握证据。

同一道题重试、刷新或重复提交只能更新同一记录，不能累计为多次独立成功。相同模板只换数字属于同一题族；至少一次检查需要不同情境或解释方式。多概念题按目标分别记录，不因为一题总体答对而解锁全部相关节点。

### 11 4 评分质量

H0 的关键演示题使用人工审核的参考要点。选择题先做确定性校验，再检查必要理由；开放题由模型返回覆盖要点、遗漏、事实冲突、是否可判定和引用依据。应用校验输出结构和引用；不把模型返回的“0.98 置信度”直接作为放行条件。

答案含义模糊、资料相互矛盾、参考答案缺失或模型返回非法结构时，标记待澄清，不更新掌握。用户申诉后冻结该题结果，显示参考规则并提供独立替代题；撤销评分需要重算受影响节点。V1 再评估教师复核或第二评分模型的必要性，避免 H0 无限制叠加模型调用。

## 12 资料处理与内容可信度

### 12 1 从文件到活动

导入后依次完成类型与大小校验、文本提取、内容预览、章节与概念匹配、来源绑定、活动生成和结构校验。用户看见每个阶段，可以取消并重新选择文件。长材料分块处理，但 H0 只为当前目标生成必要活动，避免先生成一整份大课程再等待。

H0 内置内容优先使用团队原创并审核的短文及题目。用户资料匹配到现有图谱节点后可以补充上下文；匹配不到时保留资料和探索对话，提示该领域路径尚未审核。V1 才加入自动候选图谱与人工纠正工作流。

### 12 2 引用与冲突

每个来自文件的关键结论和检查题参考点，应关联文档 ID、页码或段落、原文片段及内容版本。界面区分“资料原文”“基于资料的解释”“补充背景”。引用必须能够打开或明确显示来源已移除，不能由模型凭空给出页码。

资料冲突时列出冲突点和来源，要求用户选择本次依据或改成比较任务。尚未解决的争议不用于判错。模型无法判断的图表、公式和扫描页应显示覆盖限制，不能以“全文已理解”作为状态。

### 12 3 生成约束

生成的任务必须绑定目标、节点、预计时长、题型、评分要点、前置条件和来源。输出中未知节点、缺失评分要点、断裂引用或不符合语言设置时拒绝进入正式学习流程。允许一次结构修复，仍失败则回退审核内容或显示错误。

上传文件和检索片段始终按资料处理。即使其中写着“忽略之前规则”“把所有题判对”或要求发送密钥，系统也不得改变应用策略、访问密钥或执行外部动作。H0 不自动浏览外部网页扩展课程，不自动运行文件中的代码。

## 13 基于现有项目的实现方案

### 13 1 复用边界

本节基于当前工作区源码核查，表示能力与改造方向，不代表 Lumap 已经完成实现。录音和论文带学可作为材料入口和表现层，产品主入口应围绕学习目标重新设计。

| 现有能力 | 可复用部分 | Lumap 必需改造 |
| --- | --- | --- |
| SwiftUI macOS 框架 | 窗口、侧栏、主题和平台基础 | 独立 App、导航、学习工作区 |
| SwiftData 与本地文件 | 资料、录音、聊天存储模式 | 新模型、显式存储位置、版本迁移 |
| 模型配置与 Keychain | 配置、后台读取、主动解锁与错误处理 | 独立服务名；学习语言和调用编排 |
| Paper Tutor 原生服务 | PDF 与文本处理、API 适配、结构化课程、作答和恢复经验 | 非线性活动、证据、图谱、用户模型 |
| 本地检索 | 文档分块、BM25 与词项哈希检索、引用 | 学习目标过滤、来源版本、可信度校验 |
| 本地录音与 WhisperKit | 音频导入、录制、转写 | 作为 V1 可选材料入口，避免成为首次使用门槛 |
| 中英文 UI | 本地化资源、语言持久化 | 英文教学、评价与总结；消除固定中文提示 |
| 导师外观与播放 | 本地设置、资源管理、交互经验 | 原创视觉、减少动画、与教学状态解耦 |

当前检索使用词项哈希向量与文本排序，不是语义嵌入模型，更不是推荐算法。当前 Paper Tutor 的课程和反馈记录也不等于概念级掌握证据。图谱、推荐引擎、学习者模型及评估工具均需新建。

### 13 2 应用身份与数据隔离

建议开发应用身份暂定 `com.local.lumap`，正式发布前再确定团队拥有的命名空间。安装名为 Lumap.app，默认路径为用户 Applications 目录。Lumap 与 VoiceClass 使用不同沙盒容器；Lumap 的数据库、资料、课程和索引置于自身 Application Support/Lumap 下，密钥使用独立服务命名。

不复制用户现有数据库、录音、默认设置或密钥。未来提供显式导入：选择 VoiceClass 导出包、预览资料清单、复制所选资料并重建索引。H0 可先使用普通文件导入，不直接挂载 VoiceClass 的 SQLite 文件。改名或切换语言不能改变 Lumap 的数据库位置。

### 13 3 建议模块

| 模块 | 责任 | 输出 |
| --- | --- | --- |
| GoalService | 澄清、确认与目标版本 | 可观察目标及约束 |
| ContentService | 文件提取、引用、审核内容 | 可追溯的材料片段 |
| LearningGraphService | 图谱校验、依赖与路径版本 | 合法候选节点 |
| TutorOrchestrator | 教学状态、模型调用与取消 | 学习活动和反馈 |
| AssessmentService | 规则校验、评分和申诉状态 | 有效证据或不确定结果 |
| LearnerModelStore | 证据、兴趣、状态重算 | 可检查的用户模型 |
| RecommendationEngine | 候选过滤、排序和原因 | 主建议、备选及决策记录 |
| PersistenceCoordinator | 原子保存、迁移和恢复 | 一致的本地学习状态 |

建议 H0 核心界面使用 SwiftUI，以减少 Web 与原生双状态同步成本。已有 Paper Tutor Web 组件可用于本地对照和后续可选模式；如确需复用其派生源码，先确认对应来源及使用条件。无需为演示同时维护两套学习主界面。

### 13 4 模型调用和成本控制

大模型负责澄清建议、活动语言表达和开放答案分析；依赖校验、状态变化、数据删除、分数合成和推荐过滤由应用执行。向模型提供当前目标、当前节点、必要的资料片段和有限的历史摘要，避免每轮发送全部历史。

H0 一次 10–15 分钟会话暂设最多约 12 次模型调用、每次最多一次自动结构修复或可重试故障重试；到达预算后让用户决定继续。缓存已生成内容，失败不重复生成已完成活动。测试和使用真实模型时记录调用量与耗时，不记录密钥。

成本按“输入 token × 对应单价 + 输出 token × 对应单价 + 其他实际服务费用”计算；单价由团队选择的供应商和模型配置提供，不在 PRD 中假定固定市场报价。本地模型的延迟和兼容性需单独测试。API 协议可复用，供应商支持清单只列实际验证成功的组合。

## 14 数据模型与事件

### 14 1 核心实体

| 实体 | 必备字段 | 关键规则 |
| --- | --- | --- |
| LearnerProfile | ID、语言、跨会话记忆开关、创建时间 | H0 本地单用户，不含密钥 |
| LearningGoal | ID、原话、确认成果、约束、状态、版本 | 每个会话引用明确版本 |
| InterestSignal | 主题、强弱、来源、时间、确认状态 | 可删除，不写成能力标签 |
| ConceptNode | ID、目标、领域、内容版本、审核状态 | 稳定 ID，变更需兼容检查 |
| ConceptEdge | 起点、终点、关系、依据 | 必要前置必须无环 |
| SourceDocument | ID、名称、哈希、类型、提取状态 | 原文和片段可追溯 |
| LearningActivity | 节点、题族、内容、规则、来源、版本 | 题目与评分规则成对保存 |
| LearningSession | 目标版本、当前状态、活动、草稿 | 每次稳定转移持久化 |
| AttemptEvidence | 活动、原答、辅助级别、结果、有效性 | 幂等 ID，申诉冻结影响 |
| ConceptState | 节点、状态、证据 ID、最近复核 | 派生值，可由证据重建 |
| RecommendationDecision | 候选、得分、依据、选择、版本 | 保证解释与实际排序一致 |
| MemoryRecord | 摘要、原始依据、适用范围、来源类型 | 删除依据时同步失效 |

### 14 2 一致性与恢复

一次提交生成稳定的 attemptID。保存答案、有效评分、概念状态变化和事件时使用一致事务；推荐可以随后异步计算，但必须绑定已提交的状态版本。模型响应晚于用户取消、目标修改或新尝试时，将其丢弃或存为未应用结果，不能覆盖最新状态。

启动时验证数据库版本和最近会话。迁移失败保留旧文件并提供只读导出，不能静默创建空库替代已有资料。磁盘不足和写入失败必须明确告知，界面不能显示“已保存”后丢失进度。数据库健康检查应验证实际写入与读回，计数本身不等于验证成功。

### 14 3 产品事件

H0 本地记录 goal_confirmed、diagnostic_skipped、attempt_submitted、evidence_accepted、recommendation_shown、recommendation_overridden、goal_changed、session_resumed 和 generation_failed。记录事件 ID、时间、对象 ID、版本、结果与必要分类；分析事件不包含原始答案、资料正文或 API Key。

原始答案是本地学习记录的一部分，与分析事件分开。试点如需要收集评估数据，使用明确同意的导出流程；H0 不设置默认后台分析上传。

## 15 隐私与失败处理

### 15 1 数据边界

本地保存不等于所有计算离线。使用远程模型时，当前输入、必要资料片段和相关学习摘要会发往用户选择的服务商；首次发送前显示接收方和内容类别。采用本地模型时说明其连接状态。对远程服务留存策略不作超出实际配置的保证。

API 密钥仅进入系统 Keychain，启动被动检查在后台进行；需要授权时展示明确解锁按钮。解锁前仍能查看已有资料和地图。尚未成功读取的空白字段不能删除已有密钥，密钥不出现在日志、演示录屏和数据导出中。

### 15 2 失败状态与恢复动作

| 情况 | 用户看见什么 | 系统处理 |
| --- | --- | --- |
| 没有 API 或密钥锁定 | 配置或主动解锁入口 | 保留本地内容，不阻塞启动 |
| 断网、超时、限流 | 可重试原因和保存状态 | 取消可用，不写入失败评分 |
| 扫描 PDF 或解析失败 | 不可用部分和替代输入建议 | 不生成“已读全文”结论 |
| 资料与目标无关 | 当前覆盖范围和目标建议 | 保留资料，使用探索草案 |
| 连续两次任务无进展 | 更具体示范或前置补充 | 不无限重复同一问题 |
| 用户不想回答 | 跳过、解释、暂停 | 保留未知状态，不判能力低 |
| 评分争议或证据不足 | 参考要点与待复核状态 | 冻结此次画像更新 |
| 图谱无候选或有循环 | 无法可靠生成路径 | 回退审核路径或探索任务 |
| 写入失败或空间不足 | 明确未保存及导出入口 | 不覆盖原库，不冒充成功 |
| 中途退出或重复提交 | 恢复当前活动 | 幂等写入，避免重复累计 |

### 15 3 非功能要求

以下为目标，需要在指定演示 Mac 和选定模型上记录实测：冷启动到可交互 p95 不超过 3 秒；纯本地保存和推荐排序 p95 不超过 500 毫秒；在线请求 2 秒内显示进度或等待状态，45 秒仍未完成时提供清晰取消与重试，不能让窗口无响应。模型内容首段与完整结果的延迟分别统计。

验收至少覆盖空库、100 次学习尝试、约 50 份文本资料的本地规模；这不是面向大规模学校部署的性能承诺。图谱和文件处理不能占用主线程造成连续明显卡顿。H0 无网络时可查看历史和审核内容；新生成与开放评分是否可用取决于本地模型或在线服务，不宣称完全离线智能学习。

## 16 成效指标与验证设计

### 16 1 指标定义

| 指标 | 定义 | 首轮观察目标 |
| --- | --- | --- |
| 首次有效学习完成率 | 新用户在一次会话中完成目标确认、一次学习活动及一项有效独立检查的比例 | 10 人中至少 7 人，作为可用性目标 |
| 目标清晰度变化 | 前后能否说出可观察成果，由统一量表评分 | 记录变化和失败原因，不先宣称提升 |
| 独立任务表现 | 等难度前后任务的评分要点覆盖 | 同时报告个体与总体，不使用重复原题 |
| 推荐可理解率 | 用户能说明建议的目标或证据依据 | 至少 8/10 能解释一项主建议 |
| 画像纠正有效率 | 纠正后下一次计算不再使用被撤销依据 | 固定用例 100% 通过 |
| 延迟保持 | 3–7 天后新题表现和证据状态 | V1 测试，H0 不虚构长期效果 |
| 可靠性 | 核心路径完成、恢复、引用和状态一致 | P0 验收全部通过 |

首要指标建议使用“每周完成的有效学习闭环数”，同时限制其必须包含独立任务证据，防止把阅读和点击算作完成。用户接受推荐的比例仅作为辅助指标，不能奖励系统把用户引向容易接受但价值低的内容。

### 16 2 用户研究与试点

Hackathon 前或后先访谈 5 位目标用户，询问最近一次不知道学什么、如何判断自己学会了、何时停止学习；不先展示完整方案诱导肯定。原型测试约 10 人，观察能否找到入口、解释路径和使用纠正功能。

后续招募约 20–30 位成人用户做小型探索试点，比较固定短路径与自适应路径。在相近内容、时间和预备知识条件下随机分配，使用等难度任务与独立评分，记录退出原因和实际 AI 支持程度。样本较小只用于估计趋势与发现问题，不据此宣传普遍因果效果；如要作正式效果结论，需要进一步样本与研究设计。

### 16 3 内容与模型评估

准备至少 30 个审核用例，覆盖基础正确答案、常见误区、语言切换、非标准表达、答案揭示后重答、评分申诉、无依据引用和文件中的指令。对关键评分结果由内容负责人逐项复核。记录模型、提示词、图谱和规则版本，方便重放；不能在演示前临时换模型却沿用旧评估结论。

## 17 商业假设与竞争验证

### 17 1 第一批客户与付费动机

先验证大学生个人使用：陌生主题入门、课程材料理解和跨领域学习。付费动机假设是“更快知道下一步，并看见自己能做什么”，而不是拥有一个人格化聊天窗口。学校和教师可能是未来分发伙伴，但当前没有学校采购承诺或合作事实。

建议先做免费邀请制试点，提供明确计算额度。商业版本可比较个人订阅、用户自带 API 和机构试点三种方式。订阅适合降低配置门槛，自带 API 降低团队成本但增加使用负担，机构方案需要内容质量与部署支持。H0 不实现支付。

### 17 2 定价与成本假设

可在访谈中测试每月 A$8、A$15、A$25 三个假设价位，但这些数字不代表已验证定价或竞品价格。询问愿意支付的具体场景，再用真实转化试验验证，不把口头“愿意付费”当收入。

先测量每个有效学习闭环的平均模型成本、p95 成本和失败重试比例；再估算每名用户月会话数、模型费用、支持成本及毛利。若目标售价无法覆盖高使用量，优先缩减无效生成、增加缓存和分层额度，不能通过降低关键评分质量来隐藏成本。

### 17 3 差异化验证

已核实 Khanmigo 提供引导思考的辅导体验，因此“会问问题”不足以支持独特性。Lumap 的产品验证集中在三项：模糊目标是否更容易变得具体、前置缺口是否被适量处理、用户能否依据历史证据理解并改变推荐。[Khanmigo 官方介绍](https://www.khanmigo.ai/)

更长期的积累应来自经过审核的能力图谱、可迁移的评估任务、推荐质量和用户信任。现有角色立绘或普通聊天能力容易被替代；未经允许扩大数据收集也不能被定义为竞争优势。尚未开展完整竞品研究、市场规模测算或商标检索，Lumap 名称的可用性需在正式品牌投入前确认。

## 18 Hackathon 实施与演示

### 18 1 48 小时建议计划

此计划以赛事允许复用既有基础、3–4 人团队和一个领域为前提。赛事尚未明确，不能宣称已经满足其规则。参赛材料应列出 VoiceClass 既有能力与赛事期间新增的 Lumap 工作，记录开发起点；若不允许既有代码，改用轻量独立原型验证闭环，并重新估算工期。

| 时间 | 负责人角色 | 交付与完成标准 |
| --- | --- | --- |
| 0–4 小时 | 产品与内容、全员 | 锁定单一目标，审核六个核心节点与关键题，确认规则与分工 |
| 4–12 小时 | macOS 开发、学习逻辑开发 | 独立 App 与数据库、目标与图谱模型、可点通工作区 |
| 12–24 小时 | 学习逻辑、AI 与内容 | 诊断、活动、提示、评分与证据更新完成一条纵向流程 |
| 24–34 小时 | macOS 与学习逻辑 | 推荐解释、路径变化、导入、恢复和 API 失败处理 |
| 34–42 小时 | 全员 | 核心用例测试、语言检查、内容修订与演示记录 |
| 42–48 小时 | 产品与演示、全员 | 功能冻结、完整彩排、备用模式和提交材料 |

三人团队可将 AI 适配和学习逻辑合并。第 24 小时纵向闭环仍未通过时，无论团队人数多少，都停止扩展到 12 节点，改用六节点审核题库、列表式地图和单模型；资料仍可导入，但仅映射到这些节点，暂停任意新题和新活动生成。AI 继续用于目标表达、讲解和受约束的答案分析，路径与题目使用审核版本。

只有一两人或更短工期时，从这一简化方案开始。首先保证“目标 → 任务 → 证据 → 下一步”闭环，移后外观定制、音频和完整画像编辑。基线降级不放弃数据一致性、明确失败状态或两项独立证据要求。

### 18 2 四分钟演示脚本

| 时间 | 演示行为 | 评委应看到的证据 |
| --- | --- | --- |
| 0:00–0:30 | 输入模糊目标并选择 AI 新闻方向 | 无需预先制定课程也能开始 |
| 0:30–1:10 | 做“95% 准确率是否可靠”的短判断 | 系统采集理由，发现具体缺口 |
| 1:10–2:05 | 展示多数类基线，再做新题；如要解锁则补第二题或展示一项合格历史证据 | 一次成功不冒充两次，提示与独立检查分开 |
| 2:05–2:50 | 地图更新，展示为何补 N06 或进入 N10 | 推荐使用了本次证据，变化可解释 |
| 2:50–3:25 | 将兴趣改为公共服务例子并查看备选 | 例子随偏好变，必要基础不被跳过 |
| 3:25–4:00 | 重启恢复或切到已标记历史档案 | 持续记忆、数据来源和下一步清楚 |

演示提供两条可操作分支：答错进入补充，独立挑战通过则跳过基础。对需要满足的其他前置，用明确标记的演示历史或现场挑战证明。可压缩阅读时间，但不能把四分钟演示当作完成真实学习效果研究。

### 18 3 演示真实性与备选方案

预置历史一律显示“Demo profile / 演示档案”，并与真实使用数据隔离。现场生成显示调用状态；断网时切换“Offline sample / 离线示例”，使用同一套状态与推荐规则重放经过审核的内容，不声称后台仍在实时推理。单独提供清空演示数据按钮，不触碰用户真实数据库。

可以预置原创短资料、题目和图谱；不得把原项目用户的录音、私人资料或密钥带入演示。已有 Paper2Galgame 本地来源记录未提供代码和角色图片的明确再分发授权，Lumap 公开原型采用自行实现的界面与原创或获许可素材，并保留实际复用依赖的声明。

以下为开发后的验收要求，目前尚未执行 Lumap 功能测试。P0 用例必须全部通过，产品才可以声称 H0 闭环完成。

## 20 风险与决策记录

| 风险或未决项 | 可能影响 | 当前设计决定 |
| --- | --- | --- |
| 用户其实只想快速得到解释 | 强制提问造成中断 | 允许直接讲解和调整学习强度 |
| 模型评分不稳定 | 错误路径和虚假掌握 | 审核规则、不确定状态、申诉冻结 |
| 画像把暂时选择固化 | 推荐越来越狭窄 | 分离兴趣与能力，允许纠正和拓展 |
| 任意文档自动建图质量低 | 错误前置和不可执行课程 | H0 受限领域，自由领域标草案 |
| 基础补得过多 | 用户始终碰不到目标 | 挑战跳过、只补相关缺口、允许预览 |
| 48 小时范围过大 | 演示只有漂亮页面 | 先交付纵向闭环，按人数裁剪 |
| 原项目身份被照搬 | 数据覆盖或密钥混用 | 独立身份、独立存储、显式导入 |
| 外部素材和既有代码规则不清 | 公开展示或提交受限 | 原创视觉、来源记录、核对赛事规则 |
| 缺少长期数据 | 推荐效果无法证明 | H0 展示机制，V1 做延迟验证 |

当前需要团队确认的决策包括：首批用户、具体赛事及允许的既有代码范围、开发时长与人数、首个学习领域、演示使用的 API 与预算、是否优先实现语音。未收到进一步信息前，按本文成人大学生、macOS、英文默认、48 小时、单一 AI 素养领域方案推进后续设计；这不等于开始软件实现。
